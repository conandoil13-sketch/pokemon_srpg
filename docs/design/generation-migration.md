# 다음 세대 추가 규칙 (5세대부터) — 기획서

- 작성: 2026-11-18 · 상태: **확정**
- 지금: 1~493번, **4세대(플라티나) 기준** — `tools/fetch-pokeapi.js` 가 타입·특성을 4세대 시절 값으로 되돌려 가져온다.

## 큰 원칙 (사용자 결정)
- 지금은 4세대 그대로 둔다.
- **5세대를 넣는 순간 1~5세대 전체를 대부분 9세대 기준으로 한 번에 옮긴다.** 그 뒤 6~9세대도 9세대 기준으로 넣는다.

## 9세대 기준으로 옮기는 것 *(내 제안 — 사용자 승인)*
- 타입 (페어리 추가, 상성표 9세대)
- 종족값
- 기술의 위력·명중·타입·분류
- 특성 목록·슬롯
- 진화 정보 (옛 포켓몬의 새 진화 포함 — 단 진화 단순화 규칙은 우리 것)

## 우리 규칙이라 그대로 두는 것
- SRPG 식으로 다시 해석한 기술·특성 효과 (범위 모양, 속박, 반격, 숨기, 위치 기술 …)
- 밸런스 숫자 (HP 배율, 레벨 상한, 난이도 곡선, 회복 횟수 …)
- 진화 단순화 (돌 진화 = 진화의돌 하나, 친밀도·교환 = 레벨)
- 지니는 도구 효과·가격

## 세대 추가 단계에서는 넣지 않는 것
메가진화 · Z기술 · 다이맥스 · 테라스탈 — **모든 세대를 다 넣은 뒤 별도의 "전투 기믹 작업"에서** 다룬다 (사용자 결정 2026-11-18). 아군도 쓸지 등 범위는 그때 정함.

## 배우는 기술 목록 (사용자 결정)
- **그 포켓몬이 처음 나온 세대의 목록 ∪ 마지막으로 나온 세대의 목록** (합집합).
  - 가능함: PokeAPI 의 `pokemon.moves[].version_group_details` 가 게임(버전 그룹)별 배우는 방법·레벨을 다 준다 → "첫 등장 버전 그룹"과 "마지막 등장 버전 그룹"을 골라 합침.
  - 같은 기술이 두 목록에서 레벨이 다르면 **더 낮은 레벨** *(내 결정)*.
  - 9세대에서 빠진 기술도 기술 데이터(`MOVES`)에는 남긴다 (PokeAPI 에 있음, 위력 등은 마지막으로 있던 세대 값).
- 이유: 기존 저장의 포켓몬이 배운 기술이 사라지지 않게 (아래 저장 규칙과 연결).
- 만약 구현이 너무 복잡하면 **마지막 등장 세대 목록만** 쓰는 것으로 물러난다.

## 숨겨진 특성 (사용자 결정)
- 이제 넣을 준비를 한다. 단 **한 번에 다 넣지 않고 세대 단위로 밸런싱하며** 넣는다.
- *(내 해석)* 세대 묶음마다 그 세대 포켓몬의 숨겨진 특성을 SRPG 효과까지 정해 함께 넣는다. 1~4세대 것은 5세대 추가 때 첫 묶음.
- **얻는 방법 (사용자 결정):** 지금 특성 해금과 같은 방식으로 **계열 결정 4개** (일반 특성 해금은 3개). 해금하면 일반 특성과 자유롭게 바꿔 낄 수 있음 *(지금 해금 규칙과 같게 — 내 결정)*.

## 리전폼 (사용자 결정)
- 7·8세대를 넣을 때 같이 넣는다 (5·6세대 추가 때는 없음).

## 기존 저장 (사용자 결정 + 내 결정)
- 옮기는 순간 가진 포켓몬의 타입·종족값·특성 슬롯은 9세대 값으로 바뀐다.
- 이미 배운 기술은 그대로 — 합집합 목록이라 대부분 그대로 배울 수 있는 기술로 남음. 목록에 없는 기술이 있어도 지우지 않음 *(내 결정)*.
- 특성이 사라진 슬롯이면 같은 번호 슬롯의 새 특성으로, 해금 여부는 유지 *(내 결정)*.
- 저장 버전을 올리고 옮기는 코드를 둔다.
