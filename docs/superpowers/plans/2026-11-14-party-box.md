# 편성소 박스 화면 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 한 줄 목록 편성소를 본가식 박스(아이콘 격자 + 짧은 패널 + 출전 줄) + 자세히 보기 4페이지로 바꾸고, 특성을 "결정으로 한 번 해금 → 공짜 전환"으로 바꾼다.

**Architecture:** 순수 규칙(특성 해금·전환은 `progress.js`, 정렬·박스 나누기는 새 `src/core/box.js`, 저장 v6). 화면은 새 `src/game/box.js`(박스·메뉴) + `src/game/summary.js`(자세히 보기, box 가 띄우는 하위 화면). `party.js` 삭제.

**Tech Stack:** vanilla ES modules, Canvas 2D (256×192), `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-14-party-box-design.md` (§6 "빌더 체크 뒤 정리" 포함)

## Global Constraints
- 한 박스 30칸(6×5), 칸 24px. 왼쪽 패널 폭 104, 격자 x 108~252 · y 16~136, 머리줄 14, 출전 줄 y 140~188.
- 출전 표시 = 파란 테두리 + 모서리 깃발 (★ 금지 — 이로치용).
- 해금 비용 `ABILITY_UNLOCK_COST = 3` (계열 뿌리 결정), 멤버마다. 해금하면 바로 다른 특성으로 바뀜. 잠김 = 지금 슬롯 특성만.
- 저장 v6: v5 멤버 모두 `abilityUnlocked: false`, 슬롯 그대로.
- 정렬 `'joined' | 'level' | 'dex'`, 키 `S` = `{type:'sort'}` + 머리줄 클릭. 정렬·박스·커서는 실행 중 기억(모듈 변수), 저장 안 함.
- 출전 바꾸기·해금·특성 바꾸기마다 `onSave()`.
- 메타몽도 격자에 포함, 출전 빼기 불가(기존 거절 대사).

## Review Focus
1. 돌 진화 뒤 박스로 돌아오면 정렬·박스·커서가 그대로, 커서는 진화한 멤버(새 종 키)에. → Task 3 test.
2. 31마리 → 박스 2개, 둘째 박스는 1칸, 빈 칸으로 커서 안 감. → Task 2 test.
3. 잠긴 특성을 공짜로 바꾸려는 입력(메뉴·클릭 연타) → 거절, 결정 안 줄어듦. → Task 3 test.
4. v5 저장에서 슬롯 1 멤버 → v6 에서도 슬롯 1 + 잠김(특성 안 바뀜). → Task 1 test.
5. 출전 4마리 꽉 찬 상태에서 넣기 → "출전 자리가 꽉 찼다", 저장 호출 없음. → Task 2 test.
