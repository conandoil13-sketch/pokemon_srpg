# 마을 확장 + 상점 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 마을을 28×14 로 넓혀 상점(켈리몬)을 두고, 탐험마다 바뀌는 8칸 진열에서 코인으로 지니는 도구를 산다.

**Architecture:** 가격표는 `src/data/heldItems.js` 각 도구의 `price`. 진열·사기는 순수 모듈 `src/core/shop.js` (`rollStock`, `buy`, `refreshShop`), 저장은 `game.shop = { stock: [{ id, sold }], seq }`. 탐험 끝(`finishRun`)에서 `refreshShop`. 화면은 `src/game/shop.js` 장면 + 마을의 새 표지판 `action: 'shop'`.

**Tech Stack:** 바닐라 JS ES 모듈, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-17-town-shop-design.md`

## Global Constraints
- 가격: 150 = flame-orb, toxic-orb, sticky-barb, destiny-knot, grip-claw, damp-rock, heat-rock, smooth-rock, icy-rock · 300 = 타입 강화 17, muscle-band, wise-glasses, light-clay, mental-herb · 500 = light-ball, thick-club, deep-sea-tooth, deep-sea-scale, lucky-punch, stick · 600 = scope-lens, razor-claw, wide-lens, bright-powder, lax-incense, expert-belt, white-herb, black-sludge, shell-bell, focus-band, choice-band, choice-specs · 1200 = leftovers, life-orb, focus-sash, metal-powder.
- 진열 8칸: 150 대 3 · 300/500 대 3 · 600 대 1 · 마지막 칸 50% 로 1200 대, 아니면 600 대. 중복 없음. 각 1개.
- 시드: `createRng(hashSeed(SHOP_SALT, game.shop.seq))`; `refreshShop` 이 `seq` 를 1 올리고 다시 굴림. 불러오기는 굴리지 않음. 상점이 없는 저장은 로드 때 `seq: 0` 으로 한 번 굴림.
- 사기: 코인 ≥ 가격, 품절 아님 → 코인 차감, `items.held[id]` +1, `sold: true`.
- 마을: 각 줄 오른쪽에 8칸 이어 붙여 28 너비 (오른쪽 테두리 `#` 는 새 끝으로). 새 구역: 상점 건물 `^` 덩어리, 표지판 `{ id: 'shop', kind: 'sign', action: 'shop', lines: ['상점이다.', '도구를 살까?'] }`, 상인 NPC 켈리몬 (말 걸면 상점). `TOWN.shopSpot` = 표지판 앞. 기존 좌표는 모두 그대로.
- 브랜치 `feat/town-shop`. 테스트 `npm test`. 저장 `pokemon-tactics-save` 백업·복원.

## Review Focus
1. 넓힌 마을에서 모든 표지판·NPC·동료 자리에 걸어서 닿음, 물속 선물 자리·돌아오는 자리 그대로 → Task 2 테스트.
2. 같은 저장을 불러오기만 반복해도 진열이 그대로 → Task 1 테스트.
3. 전멸로 끝나도 진열이 바뀜 → Task 1 테스트 (`finishRun(..., 'wiped')`).
4. 사고 나서 가방 탭·박스 도구 목록에 바로 보임 (같은 `items.held`) → Task 1 테스트.
5. 코인 0 일 때 목록이 전부 회색이어도 취소로 나갈 수 있음 → Task 2 테스트.
