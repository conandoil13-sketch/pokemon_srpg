# 날씨 — 설계 스펙

- 작성일: 2026-11-14 · 상태: 사용자 리뷰 대기
- 선행: 기획 메모 `2026-11-13-stage-gimmicks-plan.md` 1단계

## 1. 목표 · 이유
층(스테이지) 조건이 전투 판단을 바꾸게 한다. 날씨에 따라 어떤 기술·포켓몬을 낼지, 어디서 싸울지가 달라진다.

### 사용자 결정
- 던전마다 **등장할 수 있는 날씨 1~2개와 확률**. 확정이 아니라 확률로 나오고, 안 나오면 날씨 없음(맑음).
- **중첩 없음**: 한 층에 날씨는 최대 하나, **층 전체 고정**.
- 확률은 **드물게**: 들판 비 15% · 쾌청 10%, 동굴 안개 15%.
- 효과는 **본가 효과 + 안개 시야만** (쾌청 물 마름·모래바람 사거리 감소 같은 지형 변화는 지형 기믹 단계로).
- 모래바람·싸라기눈 피해로 기절하면 **상태이상 피해와 같은 보상**(살아 있는 아군 전원 경험치 일부 + 코인).
- 안개: 명중 하락 + **먼 시야 제한(가벼운)**. 본격 시야 제한은 나중 "어두운 동굴".

### 성공 기준
1. 층을 만들 때 던전 날씨표로 날씨가 정해지고(같은 시드면 같은 날씨), 이어하기해도 그대로.
2. 각 날씨 효과가 §2 대로 데미지·명중·페이즈 끝 피해·상태이상에 반영된다.
3. 층 시작 배너·화면 연출·정보창에 날씨가 보인다.
4. 적 AI 의 기대 데미지 계산에도 날씨가 반영된다.
5. `npm test` 통과, 브라우저(또는 오프라인 미리보기)로 연출 확인.

### 범위 밖 · 안티 목표
- 날씨 기술(비바라기·쾌청·모래바람·싸라기눈 기술로 날씨 바꾸기), 특성(쓸쓸한 비 등), 지형 변화, 본격 시야 제한, 전설 전용 날씨.
- **안티 목표**: 날씨 연출이 유닛·대사·HP 를 가리면 실패 (연출은 반투명·맵 층, UI 아래). 날씨 때문에 층이 불공평하게 막히면 실패 (모래바람·싸라기눈 피해는 1/16 로 약하게, 지금 던전엔 아예 안 나옴).

## 2. 날씨 규칙 (본가 4세대)

| 날씨 | 데미지 | 그 밖 | 페이즈 끝 피해 |
|---|---|---|---|
| 비 `rain` | 물 ×1.5, 불꽃 ×0.5 | 번개 **반드시 명중**(최종 100, 회피 무시 — 본가 4세대) | — |
| 쾌청 `sun` | 불꽃 ×1.5, 물 ×0.5 | 얼음 상태에 걸리지 않음(이미 얼었으면 페이즈 시작에 녹음), 번개 **기본 명중이 50**(그 뒤 회피 등은 그대로) | — |
| 모래바람 `sand` | — | 바위 타입 특수 방어 ×1.5 | 바위·땅·강철 외 최대 HP 1/16 (최소 1) |
| 싸라기눈 `hail` | — | 눈보라 **반드시 명중**(최종 100) | 얼음 외 최대 HP 1/16 (최소 1) |
| 안개 `fog` | — | 모든 기술 명중 −10%p (최종 0~100) | — |

- 날씨 배율은 STAB·상성과 같이 곱한다(급소·난수 전). 기대 데미지(AI·예상 창)에도.
- 페이즈 끝 날씨 피해는 상태이상 피해와 같은 시점(끝나는 편 유닛, 랭크 만료 전)에 같은 방식으로: 이벤트 `{ kind: 'sand'|'hail', damage, hpBefore, maxHp, x, y }`, 기절 시 `knockOut(…, null)`(공유 보상).
- **안개 먼 시야** (빌더 체크 뒤 정리 — 내 결정): 기술 사거리가 최대 4라 "흐린 적을 공격"하는 일은 없다. 그래서 안개는 **정보를 가리는 기믹**이다.
  - **흐림 판정은 실시간**: 아군 어느 유닛과도 맨해튼 거리 **5 이상**인 적은 흐림 — 맵에서 어두운 실루엣, 정보창 이름·타입·HP "???". 아군이 다가가 4칸 안에 들면 바로 드러난다(정찰).
  - **적 차례**: 흐린 적이 움직여도 실루엣 그대로, 카메라는 따라가되 정보창은 "???". 이동을 마치고 아군 4칸 안이면 드러난 뒤 행동.
  - **적 AI**: **적 차례 시작 때** 적 어느 유닛과도 5 이상 떨어진 아군 목록을 한 번 정해, 그 아군들은 이번 차례 공격 대상·위협 계산에서 뺀다(다가가는 목표로는 씀). 한 적이 다가갔다고 다른 적이 알게 되지는 않는다.

## 3. 날씨 정하기
- `dungeons.js` 각 던전에 `weather: [{ id, chance }]` (합 ≤ 1). 들판 `[{rain, 0.15}, {sun, 0.10}]`, 동굴 `[{fog, 0.15}]`. 모래바람·싸라기눈 규칙은 만들되 지금 던전에는 없음.
- `rollWeather(dungeon, seed) => id | null` — 층 시드에서 **별도 난수**로 굴려 지형 생성 결과는 그대로(기존 시드 맵이 바뀌지 않게).
- `generateFloor` 결과 `map.weather` 에 담고 `createBattle` 이 `state.weather` 로.

## 4. 화면
- 층 시작 배너 부제에 날씨: "신오 들판 B2F · 1턴째 · 비". 정보창 오른쪽 위 작은 날씨 글자(비/쾌청/모래바람/싸라기눈/안개).
- 연출 (화면 고정 층, 유닛 위·UI 아래, 반투명). pixelfx `weather` 효과는 바닥·안개까지 그린 장면이라, **빗줄기·눈송이 같은 입자 층만 쓸 수 있으면 pixelfx, 아니면 코드로 그린 가벼운 덮개**(빗줄기 사선, 눈송이, 안개 띠, 햇살 색조, 모래 입자)로 대신한다 (내 결정, 빌더가 렌더해 보고 결정): 비 `weather/rain`, 쾌청 `weather/god-rays`(약하게), 모래바람 `weather/fog`(먼지색 팔레트) 또는 `weather/snow` 먼지색, 싸라기눈 `weather/snow`, 안개 `weather/fog`. 320×180 효과를 256×192 화면 중앙에 맞춰 그림(넘치는 부분 잘림).
- 날씨 피해 대사: "○○는 모래바람에 휘말렸다!" / "○○는 싸라기눈을 맞았다!" (상태이상 피해처럼 HP 바·카메라).
- 기술 예상 창: 날씨로 강해지면 데미지 옆에 작은 ▲, 약해지면 ▼ (선택, 빌더 재량).

## 5. 아키텍처
```
src/core/weather.js     (신규, 순수) WEATHER 표, rollWeather, weatherDamageMult, weatherAccuracy, weatherImmune(ailment), phaseEndWeather(unit, weather)
src/data/dungeons.js    weather 확률표
src/core/floorgen.js    map.weather
src/core/battle.js      state.weather, 페이즈 끝 날씨 피해 이벤트, 쾌청 얼음 해제·면역
src/core/damage.js      baseDamage·hitChance 에 날씨 (state 없이 쓰므로 move/attacker/defender + weather 인자)
src/core/status.js      canInflict 에 날씨(쾌청 → 얼음 불가)
src/core/ai.js          기대 데미지에 날씨, 안개 먼 아군 제외
src/game/states.js      배너·정보창 날씨, 안개 흐림 처리, 날씨 연출
src/data/moveFx.js / src/render/fx.js   날씨 루프 (vendor 에 weather 효과 추가)
```
- 데미지 함수에 날씨를 넘기는 방법: `calcDamage(…, { weather })`, `expectedDamage(…, weather)`, `hitChance(…, weather)` — 기본값 null(지금과 같음).
