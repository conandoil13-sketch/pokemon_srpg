# 메타몽 빌드 — 설계 스펙

- 작성일: 2026-11-14 · 상태: 빌더 체크 완료, 사용자 승인 대기

## 1. 목적 · 이유
메타몽은 이 게임의 주인공이다. 사용자는 메타몽을 **페르소나5 주인공처럼** 쓰고 싶다: 다른 동료는 종족 그대로 크지만, 메타몽만은 **타입 조합부터 능력치·기술·특성까지 플레이어가 원하는 대로 키우는 "내가 만드는 포켓몬"**. 지금 메타몽은 종족값 48 일색 + 몸통박치기 하나라서, 이 기능이 메타몽의 존재 이유가 된다.

### 사용자 결정
- **B안: 본체 하나를 키운다.** 전투 중 모습 바꾸기 없음. 전투 전에 짜 둔 메타몽으로 싸운다.
- 타입(1~2), 능력치, 기술 4개, 특성 1개를 모두 플레이어가 정한다.
- **메타몽 캡슐**: 적을 쓰러뜨리면 일정 확률로 떨어진다. 안에 **그 적과 관련된 것 하나**(타입·기술·특성, 나중에 무게 등)가 무작위로. **소모품** — 쓰면 메타몽에 적용되고 사라진다. 바뀌어 빠진 것은 사라진다.
- **능력치 강화 = 파우더** (본가 메탈파우더·스피드파우더 모티브): 능력치마다 따로(체력·공격·방어·특공·특방·스피드 파우더). 지금은 보물상자, 나중엔 상점.
- **능력치 합계 상한이 10레벨마다 올라간다** (A안).
- 10레벨마다 무언가 해금.
- 구현: 1안 — 빌드를 메타몽 멤버 데이터로 저장, 규칙은 순수 모듈, 전투의 타입·종족값 읽기를 "유닛 기준"으로 모은다.

### 성공 기준
1. 던전에서 적을 쓰러뜨리면 가끔 캡슐을 얻고(탐험 보상), 보물상자에서 파우더를 얻는다.
2. 박스에서 메타몽 빌드 화면을 열어 캡슐·파우더를 써서 타입·기술·특성·능력치를 바꾼다.
3. 바뀐 메타몽이 전투에서 그 타입(상성·면역·날씨·지형)·능력치·기술·특성으로 싸운다.
4. 적 메타몽·다른 동료는 영향 없음. 기존 저장이 그대로 불러와진다.
5. `npm test` 통과, 브라우저 확인.

### 범위 밖 · 안티 목표
- 범위 밖: 상점, 무게(헤비봄버), 파우더 초기화 아이템, 전투 중 변신, 다른 동료 커스터마이즈, 캡슐 버리기·팔기.
- **안티 목표**: 메타몽 빌드가 다른 유닛(적 메타몽·동료)에 새면 실패. 빌드 때문에 메타몽이 "모든 능력치 최대"가 되면 실패(상한). 캡슐을 실수로 써서 원하던 기술을 잃는 게 확인 없이 일어나면 실패.

## 2. 규칙

### 2-1. 빌드 데이터 (메타몽 멤버에만)
`member.build = { types: ['normal'] | [t1, t2], bonus: { hp, atk, def, spa, spd, spe }, ability: 'limber' }`
- 기술은 기존 `member.moves` (최대 4) 그대로 쓴다. 메타몽은 레벨업으로 기술을 배우지 않는다(종 습득표가 변신뿐 — 지금도 그렇다).
- 처음: 노말, bonus 전부 0(종족값 48×6 = 288), 몸통박치기, 유연.
- 실제 종족값 = 48 + bonus (각각). 이동력은 메타몽 종족 그대로.

### 2-2. 능력치 상한 · 파우더
- `POWDER_STEP = 10` (파우더 하나 = 그 능력치 종족값 +10).
- 합계 상한 `statCap(level) = min(600, 320 + 40 × floor(level / 10))` — Lv.1~9 320, Lv.10 360, … Lv.70 이상 600. (숫자는 밸런싱으로 조정 가능)
- 파우더 쓰기: 합계 + 10 ≤ 상한이어야 함, 한 능력치는 최대 255. 안 되면 거절(아이템 안 줄어듦).
- 파우더 종류 id: `powder-hp | powder-atk | powder-def | powder-spa | powder-spd | powder-spe`, 이름: 체력파우더 · 공격파우더 · 방어파우더 · 특공파우더 · 특방파우더 · 스피드파우더.

### 2-3. 10레벨 해금
- 매 10레벨: 상한 +40 (위).
- **Lv.10: 두 번째 타입 칸 열림.** 그 전에는 타입 캡슐로 첫 번째 타입만 바꿀 수 있음.

### 2-4. 메타몽 캡슐
- 내용: `{ kind: 'type' | 'move' | 'ability', value, from: 적 종 }`. 나중 확장(무게 등)을 위해 kind 는 열린 목록.
- **떨어지는 조건**: 아군 차례든 상태이상·날씨든, 보상이 있는 적 기절(지금 코인이 붙는 기절)마다. 확률 **15%**, **보스는 100%**. (`CAPSULE_CHANCE = 0.15`)
- **내용 고르기**: 그 적의 타입들 · 그 적이 가진 기술 중 배울 수 있는 것(`MOVES[id].learnable` 또는 `tackle`) · 그 적의 특성(`unit.ability`) 후보 전체에서 균등 무작위 하나.
- **언제 굴리나**: 전투 로그에 쓰러뜨린 적 정보(종·타입·기술·특성·보스 여부)를 남기고, 층을 마친 뒤(`afterBattle`) `rollCapsules(defeated, rng)` 로 굴려 탐험 보상(`run.loot.capsules`)에 담는다. 탐험 보상과 같이: 귀환·클리어하면 가방으로, 전멸하면 잃는다.
- **쓰기 (소모)**:
  - 기술 캡슐: 기술 칸(1~4, 빈 칸 있으면 빈 칸도) 골라 그 자리에 넣음 → 원래 기술 사라짐. 이미 같은 기술이 있으면 못 씀.
  - 타입 캡슐: 타입 칸 골라 바꿈(Lv.10 전엔 1칸, 이후 2칸 — 둘째 칸이 비었으면 추가). 다른 칸과 같은 타입이면 못 씀.
  - 특성 캡슐: 특성을 바꿈. 지금 특성과 같으면 못 씀. 이 게임에서 효과 없는 특성도 쓸 수는 있음(회색 표시).
  - 쓰기 전 확인 대사("○○을 잊고 ○○을 넣을까?" / "타입을 ○○에서 ○○로 바꿀까?") — 예/아니오.

### 2-5. 보물상자 파우더
- 보물상자 아이템에 `powder`(종류 무작위 6가지 중 하나) 추가. **상자 위치·수는 그대로**, 아이템 비율만: 진화의돌 15% · 파우더 10% · 사탕 45% · 코인 30% (지금 진화의돌 15 · 사탕 55 · 코인 30 에서 사탕 몫 10%p). 파우더 종류는 상자마다 결정적 무작위(층 시드).
- 탐험 보상 → 가방은 다른 보물과 같은 방식.

### 2-6. 저장 v7
- v6 → v7: 메타몽 멤버에 `build` 기본값, `game.items.powders = { hp:0, atk:0, def:0, spa:0, spd:0, spe:0 }`, `game.items.capsules = []` (최대 200개, 넘치면 오래된 것부터 버림).
- `cleanMember`: 메타몽의 build 검증(타입 1~2개·실제 타입 id·중복 없음·Lv.10 전 2개면 1개로, bonus 0 이상 정수·각 255-48 이하·합계 상한 넘으면 상한까지 깎기(체력부터가 아닌 큰 값부터 — 빌더 재량), ability 는 `ABILITIES` 에 있는 id 아니면 limber). 메타몽이 아닌 멤버의 build 는 버린다.
- 캡슐 검증: kind 알려진 것·value 유효(타입 id / MOVES learnable / ABILITIES)·from 은 종 id, 아니면 버림.
- run.loot: `capsules: []`, `powders: { … }` 추가(v6 run 은 빈 값).

## 3. 전투 반영
- 유닛에 `types` 필드: makeUnit 이 기본 `SPECIES[species].types`, 메타몽 아군이면 `build.types`. 아군 메타몽의 `stats = statsAt(effectiveBase(build), level)`, `ability = build.ability`.
- **타입을 읽는 곳을 모두 `unit.types` 로**: `abilities.typesOf`(색변환·포캐스트 덮어쓰기 유지), `abilities.traps`, `status.js` 면역, `weather.js` 모래바람·싸라기눈 면역, `pathfind.canEnter`(물 칸 — 종 키 대신 유닛 타입), AI, 화면 정보창 타입 배지(`ui.drawUnitInfo`). 이 밖의 `SPECIES[x].types` 읽기도 유닛이 있으면 유닛 기준.
- 특성 표시·이벤트는 지금처럼 `unit.ability`.
- 결산·박스 등 멤버 화면의 메타몽 타입·특성은 빌드 기준(`abilityOf(m)` 이 메타몽이면 `build.ability`, 새 `typesOfMember(m)`).

## 4. 화면
- **박스 → 메타몽 메뉴에 `메타몽 빌드`** (다른 동료엔 없음). 자세히 보기의 메타몽 특성 페이지는 "빌드에서 바꾼다" 안내.
- **빌드 화면** (한 화면 + 가방 목록):
```
┌ 메타몽 Lv.12 ─────────── 능력치 합계 318/360 ┐
│ 타입 [노말][ — 🔒Lv.10]   특성 유연          │
│ HP 48 ▮▮▮   공격 58 ▮▮▮▮ …  (파우더로 +10)   │
│ 기술 몸통박치기 / 불꽃세례 / — / —           │
├ 가방 ─ 캡슐 7 · 파우더 3 ───────────────────┤
│ ▶ 기술 캡슐: 물대포 (꼬부기)                 │
│   타입 캡슐: 강철 (코일)                     │
│   공격파우더 ×2                              │
└──────────────────────────────────────────┘
```
- 가방 목록에서 고르기 → 캡슐이면 넣을 칸 고르기 → 확인 대사 → 적용·저장. 파우더면 확인 → +10·저장, 상한·255 면 거절 대사.
- 쓸 수 없는 항목(같은 기술 이미 있음 등)은 회색 + 고르면 이유 대사.
- **탐험 중 획득 표시**: 결산 화면에 "캡슐 +n", 층 사이 메뉴의 보물 줄에 캡슐·파우더 수. 보물상자 대사 "○○파우더를 얻었다!".

## 6. 테스트
- 규칙: statCap 표, 파우더 상한·255 거절, 캡슐 쓰기 3종(같은 것 거절·Lv.10 전 2번째 타입 거절·소모), rollCapsules 확률(1만 번 ≈15%)·보스 100%·내용이 그 적 것.
- 전투: 불꽃/강철 메타몽이 물 기술 ×2·독 면역(강철)·모래바람 피해 없음(강철), 물 타입 메타몽이 물 칸 진입, 능력치가 빌드 반영, 적 메타몽은 노말 그대로.
- 저장: v6 → v7 기본 빌드·빈 가방, 잘못된 빌드·캡슐 정리, 메타몽 아닌 멤버 build 버림.
- 보물상자: 같은 시드의 상자 위치·수 그대로, 파우더 비율 ≈10%.
- 화면: 빌드 화면에서 기술 캡슐 → 칸 고르기 → 확인 → 적용·저장·소모, 취소하면 그대로; 파우더 상한 거절 대사.

## 7. 빌더 체크 뒤 정리 (내 결정, 바꿔도 됨)
- **빌드 화면은 마을(박스)에서만.** 탐험 중 얻은 캡슐·파우더는 탐험 보상(`run.loot`)에 있다가 귀환·클리어 때 가방으로. 탐험은 층 시작마다 저장되므로(`game.run`) 이어하기해도 보상이 남는다. 전멸이면 잃는다 — 지금 보물과 같음.
- **두 번째 타입 칸은 비울 수 있다** (공짜, 확인 대사 뒤). 빠진 타입은 사라짐. 파우더는 되돌릴 수 없다(사용자 승인 — 나중 초기화 아이템).
- **보스** = 이미 있는 `unit.boss` 플래그(보스 층의 보스 하나). 그 적은 캡슐 100%.
- **가방 캡슐 상한 200** 은 넘칠 때 결산 화면에 "가방이 가득 차 오래된 캡슐 n개를 버렸다" 표시 (조용히 버리지 않음).
- **후보가 빌 일 없음**: 적은 항상 타입·특성이 있다(적 특성은 makeUnit 이 정함). 배울 수 없는 기술만 빠진다.
- **기술 쓰는 곳**: 메타몽은 레벨업 습득표가 변신(배울 수 없음)뿐이라 레벨업·진화로 `moves` 가 바뀌지 않는다. `cleanMember` 는 기술이 비면 시작 기술로 채운다(메타몽은 몸통박치기) — 그대로 둔다. PP 개념 없음.
- **빌드는 아군 메타몽(멤버에서 만든 유닛)에만.** 적 메타몽은 지금 나오지 않지만(encounters 제외) makeUnit 경로에서도 적용 안 됨을 테스트.
- 효과 없는 특성 회색 = 이미 있는 `ABILITIES[id].inactive`.
- 타입 읽기 전환 완료 확인: 저장소 전체에서 `SPECIES[…].types` 를 찾아 유닛이 있는 곳은 모두 `unit.types`(또는 멤버면 `typesOfMember`)로. 상성·자속(STAB)은 `typesOf` 를 거치므로 함께 바뀜.
- 상한·확률·파우더 수치는 `dittoBuild.js` 한곳의 상수, 테스트는 상수를 참조.

## 8. 빌더 재량
화면 배치 세부, 막대 색, 확인 대사 문구, 캡슐 목록 정렬(최근 순 권장), 상한 초과 시 깎는 순서.
