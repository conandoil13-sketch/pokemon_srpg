# 포켓몬 SRPG 브라우저 데모 — 설계 스펙

- 작성일: 2026-11-12
- 상태: 사용자 승인 대기 (설계 대화는 승인됨)

## 1. 목표

브라우저에서 바로 열어 끝까지 플레이할 수 있는 **SRPG 전투 1판**을 만든다.
4~5세대(DS) 도트 감성의 화면, 포켓몬식 타입 상성 전투, 적 AI, 공격 시 배틀 컷인을 갖춘다.

### 성공 기준
1. `index.html`을 로컬 정적 서버로 열면 타이틀 → 전투 → 승리/패배 화면까지 오류 없이 진행된다.
2. 아군 4 vs 적 5 전투에서 이동·기술 선택·대상 지정·데미지·기절이 규칙대로 동작한다.
3. 상성(효과가 굉장했다 / 별로인 듯하다 / 효과가 없다)이 메시지와 데미지에 반영된다.
4. 적 페이즈에 AI가 합리적인 행동(때릴 수 있으면 때리고, 아니면 접근)을 한다.
5. `assets/sprites/` 에 PNG를 넣으면 해당 유닛 그래픽이 교체되고, 없으면 임시 도트로 표시된다.
6. `node --test` 로 core 로직 테스트가 전부 통과한다.

### 범위 밖 (YAGNI)
레벨업/육성, 스토리, 세이브, 상태이상·능력치 변화 기술, 사운드, 여러 맵, 모바일 터치 최적화.

## 2. 스프라이트 정책

- 프로젝트는 포켓몬 공식 스프라이트(팬 커뮤니티 배포본 포함)를 **포함하지 않는다**.
- 사용자가 로컬에서 스프라이트 팩을 지정 폴더에 넣으면 자동 적용된다.
- 파일이 없으면 코드로 그린 **오리지널 임시 도트**(타입 색 기반 실루엣)로 대체한다.

### 폴더 규격
| 경로 | 용도 | 기대 규격 |
|---|---|---|
| `assets/sprites/icons/{dex}.png` | 맵 위 유닛 | 가로 2프레임 시트 (예: 64×32 = 32×32 ×2, 또는 128×64 = 64×64 ×2). 높이 = 프레임 크기, 프레임 수 = 너비/높이 |
| `assets/sprites/front/{dex}.png` | 컷인 (상대 측) | 정사각형 단일 이미지 (예: 96×96) |
| `assets/sprites/back/{dex}.png` | 컷인 (공격자 측) | 정사각형 단일 이미지 (예: 96×96) |

`{dex}` 는 전국도감 번호, 3자리 0 패딩 없이 정수 (`25.png`). 로딩 실패는 조용히 폴백한다.
그리기 시 대상 영역에 맞춰 **정수 배율 또는 정수 축소**로 nearest-neighbor 렌더링한다.

## 3. 화면 / 그래픽

- 내부 캔버스 **256×192**, CSS로 정수 배율 확대(창 크기에 맞는 최대 정수, 최소 2), `image-rendering: pixelated`.
- 타일 16×16, 맵 16×12칸 (정확히 화면을 채움). 하단/측면 정보창은 맵 위에 오버레이.
- 타일 종류(코드로 그린 도트):
  | 타일 | 이동 비용 | 효과 |
  |---|---|---|
  | 풀 `.` | 1 | — |
  | 수풀 `"` | 1 | 그 칸의 방어자 회피 +15% |
  | 바위산 `^` | 2 | 그 칸의 방어자 방어/특방 ×1.2 |
  | 물 `~` | 1 (물·비행만 진입) | 그 외 진입 불가 |
  | 벽/나무 `#` | 진입 불가 | — |
- UI: DS풍 둥근 모서리 창(흰 바탕, 진한 테두리), 코드에 내장한 5×7 비트맵 픽셀 폰트(영문·숫자·기본 기호).
  - 결정: 게임 내 텍스트는 **영어**로 한다. 256×192 해상도에서 한글을 선명한 도트로 그리려면 별도 한글 비트맵 폰트가 필요해 데모 범위를 넘기 때문. 문서·주석은 한국어.
- HP 바: >50% 초록, >20% 노랑, 그 외 빨강. 데미지 시 바가 줄어드는 애니메이션.
- 유닛 아이콘은 2프레임 idle 애니메이션(약 0.5초 간격). 아군 파랑, 적 빨강 발밑 표식.

## 4. 전투 규칙

### 4.1 진행
- 페이즈제: **Player Phase** → **Enemy Phase** 반복. 페이즈 시작 시 배너 표시.
- 각 유닛은 페이즈당 1회: 이동(선택) → 행동(기술 또는 대기). 행동을 마치면 회색 처리.
- 승리: 적 전멸 / 패배: 아군 전멸.

### 4.2 유닛 데이터
`{ species, side, x, y, hp, maxHp, moved, acted }`
종족 데이터: `{ dex, name, types[1..2], stats{hp,atk,def,spa,spd,spe}, move(이동력), moves[2..4] }`
데모는 레벨 고정(50)으로 실능력치를 미리 계산해 데이터에 넣는다.

### 4.3 기술 데이터
`{ id, name, type, category: 'physical'|'special', power, accuracy, range: [min,max] }`
사거리는 맨해튼 거리. 근접 기술 [1,1], 원거리 [1,2] 또는 [2,3].

### 4.4 데미지
```
base = floor( floor( (2*50/5+2) * power * A / D ) / 50 ) + 2
dmg  = floor( base * STAB(1.5) * typeMult * crit(1.5, 1/16) * rand[0.85,1.00] )
```
- A/D: 물리=공격/방어, 특수=특공/특방. 바위산 방어 보정 적용.
- typeMult = 18타입 상성표, 이중 타입 곱. 0이면 데미지 0, "It doesn't affect..." 메시지.
- typeMult > 0 이면 최소 1.
- 명중: `accuracy - 회피` (회피 = 수풀 15 + max(0, (방어자 spe - 공격자 spe)/10), 상한 30).
- 난수원은 주입 가능(테스트용 시드 RNG).

### 4.5 반격
없음 (포켓몬식 일방 공격). 데모의 단순성을 위해.

## 5. 적 AI

각 적 유닛을 스피드 내림차순으로 처리:
1. 이동 가능 칸 집합(BFS, 아군/적 유닛 칸 통과 규칙: 같은 편 통과 가능, 다른 편 불가, 정지는 빈 칸만).
2. 모든 (칸, 기술, 대상) 조합에 점수:
   `score = 기대데미지(평균 난수, 명중 반영) + (기절시키면 +100) − 0.5 × 해당 칸에서 받을 수 있는 최대 위협`
   위협 = 아군 각 유닛이 다음 턴 그 칸을 공격할 수 있을 때의 최대 기대 데미지.
3. 공격 가능한 조합이 있으면 최고 점수 실행.
4. 없으면 가장 가까운(경로 거리) 아군에 가장 가까워지는 칸으로 이동 후 대기.

## 6. 배틀 컷인

공격 실행 시 맵 위에 256×192 컷인 화면:
- 배경: 5세대풍 그라데이션 + 원형 받침대 2개.
- 공격자 뒷모습(좌하), 대상 앞모습(우상), 양측 HP 창.
- 연출: 공격자 전진 → 대상 깜빡임 → HP 바 감소 → 메시지("Super effective!" 등) → 기절 시 대상 아래로 사라짐 → 맵 복귀.
- 스페이스/클릭으로 메시지 넘김, 전체 약 1.5~2.5초.

## 7. 조작

- 마우스: 클릭으로 유닛 선택/이동/대상 지정. 우클릭 = 취소.
- 키보드: 방향키 커서, Z/Enter = 결정, X/Esc = 취소, E = 턴 종료.
- 커서 위 유닛 정보창(이름, 타입, HP) 표시. 선택 시 이동 범위(파랑), 공격 범위(빨강) 하이라이트.
- 상태 머신: `idle → unitSelected(이동범위) → moved(행동메뉴) → moveChosen(대상선택) → animating → idle`, 취소 시 한 단계 되돌림(이동 후 취소 시 원위치 복귀).

## 9. 아키텍처

```
index.html            캔버스 + 모듈 로드
src/
  data/types.js       18타입 상성표, 타입 색
  data/moves.js       기술 정의
  data/species.js     종족 정의
  data/map.js         맵 + 초기 배치
  core/rng.js         시드 RNG
  core/damage.js      데미지/명중/상성 (순수)
  core/pathfind.js    이동 범위 BFS, 공격 범위 (순수)
  core/ai.js          적 행동 결정 (순수, 결과는 행동 객체)
  core/battle.js      상태(유닛 목록, 페이즈, 승패) 갱신 (순수)
  render/screen.js    캔버스 셋업, 정수 배율
  render/font.js      픽셀 폰트
  render/tiles.js     타일 도트 그리기
  render/sprites.js   스프라이트 등록소 + 폴백 도트
  render/ui.js        창, HP 바, 메뉴
  render/cutin.js     배틀 컷인 연출
  game/input.js       마우스/키보드 → 커서 이벤트
  game/states.js      상태 머신
  main.js             루프 (requestAnimationFrame)
tests/                node:test, core 전용
```

경계: `core/` 는 DOM·캔버스를 모르고, `render/` 는 규칙을 모른다. `game/` 이 둘을 잇는다.

## 10. 오류 처리

- 스프라이트 404/디코드 실패 → 폴백, 콘솔 경고 1회.
- `file://` 로 열면 ES 모듈이 막히므로 README에 `python3 -m http.server` 실행법 명시.
- 로직 불변식 위반(예: 존재하지 않는 기술 id)은 데이터 로드 시 검증해 즉시 오류.
