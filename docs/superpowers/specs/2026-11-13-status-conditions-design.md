# 상태이상 — 설계 스펙

- 작성일: 2026-11-13
- 상태: 사용자 리뷰 대기 (빌더 체크 반영)
- 선행: 능력치 랭크 · 변화기 (main `1518d80`)

## 1. 목표 · 이유

본가 포켓몬 규칙(4~5세대 기준)의 **상태이상**을 넣는다: 마비 · 화상 · 독 · 맹독 · 잠듦 · 얼음 · 혼란.

- 왜: 지금 버려지는 기술(전기자석파 · 수면가루 · 도깨비불 · 이상한빛 …)과 공격기 부가효과(불꽃세례 화상 10% …)를 살리고, SRPG에서 "적 하나를 묶는" 전술을 만든다.
- 사용자 결정: 본가 규칙 기준, SRPG 번역은 아래 §3 표대로. 층이 끝나면 상태이상 회복. 구현은 랭크 때와 같은 방식(별도 순수 모듈 + 기존 흐름에 끼워 넣기).

### 성공 기준
1. 상태이상 기술을 배우고 쓸 수 있으며, 공격기 부가효과가 확률대로 상태이상을 건다.
2. 각 상태이상이 §3 규칙대로 동작한다 (잠듦·얼음 턴 통째로 쉼, 마비 이동력·스피드 절반 + 25% 기술 실패, 화상·독·맹독 페이즈 끝 데미지, 혼란 자해).
3. 타입 면역(4세대)과 "이미 상태이상" 판정이 맞다.
4. 적 AI 가 상태이상 기술을 합리적으로 쓰고, 자신이 잠듦·얼음이면 쉰다.
5. 화면: 정보창·맵에 상태 표시, 걸림·해제·데미지·실패 대사.
6. `npm test` 통과, 브라우저에서 확인.

### 범위 밖 (안티 목표 포함)
- 풀죽음(flinch), 헤롱헤롱, 씨뿌리기, 하품, 잠재우기와 연계되는 기술(꿈먹기·잠꼬대·코골기), 잠자기(rest), 트라이어택(무작위 3종).
- 특성(면역 특성 등), 치료 아이템, 마을 회복 — 층이 끝나면 전부 회복이므로 지금은 불필요.
- 뻐기기·부추기기는 계속 배우지 않음(혼란 + 상대 강화 조합이 플레이어에게 손해 — 지난 리뷰 결정 유지).
- **안티 목표**: 상태이상 때문에 플레이어가 아무것도 못 하는 층이 나오면 실패. 적 AI 가 잠듦을 연타해 아군 전체를 영구히 묶지 않도록 (§7).

## 2. 데이터 (PokeAPI)

`tools/fetch-pokeapi.js` 가 기술마다 추가 저장:
- `ailment`: `meta.ailment.name` 중 `paralysis | burn | poison | sleep | freeze | confusion` 만, 그 외 `null`
- `ailmentChance`: `meta.ailment_chance` (0 → 100%)
- 맹독: PokeAPI 는 맹독독니·맹독을 `poison` 으로 준다 → `BAD_POISON = { toxic, 'poison-fang' }` 기술은 `ailment: 'toxic'` 으로 저장.

**learnable** 규칙 확장: 공격기(위력 있음) ∨ 변화기 중 (a) 기존 랭크 변화기(`net-good-stats`) ∨ (b) `effectKind === 'ailment'` ∧ `ailment` 지원 ∧ 대상이 §3(랭크 스펙) 대상표에 있음.
→ 해당: 전기자석파·뱀눈초리·저리가루, 도깨비불, 독가루·독가스·맹독, 수면가루·노래하기·최면술·버섯포자·풀피리·악마의키스·다크홀, 이상한빛·초음파·천사의키스. 흔들흔들댄스(`all-other-pokemon`)는 대상표 밖이라 제외.

## 3. 규칙 (본가 4~5세대 → SRPG)

"턴" = 그 유닛 편의 페이즈. 페이즈 **시작** 처리 = 그 편 페이즈가 열릴 때(배너 뒤), **끝** 처리 = 랭크 감소와 같은 `endPhase` 시점.

| 상태 | 걸릴 때 | 효과 | 풀림 |
|---|---|---|---|
| 마비 | — | **이동력 절반**(내림, 최소 1), **스피드 ×0.5**(턴 순서·회피 계산), 기술 사용 시 **25% 실패** ("몸이 저려서 움직일 수 없다!", 행동 종료, 이동은 이미 끝난 상태) | 층 끝 |
| 화상 | — | 페이즈 끝 최대 HP **1/8** 데미지, **물리 기술 데미지 ×0.5** (기대 데미지·예상 창에도 반영) | 층 끝 |
| 독 | — | 페이즈 끝 최대 HP **1/8** | 층 끝 |
| 맹독 | 카운터 n = 1 | 페이즈 끝 최대 HP **n/16**, 그 뒤 n += 1 (최대 15) | 층 끝 |
| 잠듦 | 남은 수면 1~3 (rng) | 페이즈 **시작**: 남은 수면 > 0 이면 1 줄이고 **이동·행동 모두 불가**(그 페이즈 acted), 0 이면 깨어나 바로 행동 | 깨어남 / 층 끝 |
| 얼음 | 남은 얼음 3 | 페이즈 **시작**: 20% 로 녹아 바로 행동, 아니면 남은 얼음 −1 하고 **이동·행동 불가**; 남은 얼음이 0 이면 반드시 녹아 행동 (최대 3턴 쉼, 사용자 결정). **불꽃 공격기에 맞으면** 즉시 녹음 | 녹음 / 층 끝 |
| 혼란 | 남은 턴 1~4 (rng) | 이동은 정상. 기술 사용 시 **50%** 로 자신을 공격(위력 40 · 타입 없음 · 물리 · 급소·상성·명중 없음, 자기 공·방 랭크와 화상 반영) 하고 행동 종료. 페이즈 **끝**에 남은 턴 −1, 0 이면 "혼란이 풀렸다" | 0 / 층 끝 |

- **주 상태이상**(마비·화상·독·맹독·잠듦·얼음)은 하나만. 이미 있으면 새로 걸리지 않음 → 변화기라면 "효과가 없는 것 같다", 부가효과라면 조용히 무시. 혼란은 주 상태이상과 **겹칠 수 있음**, 이미 혼란이면 다시 안 걸림.
- 순서: 마비 실패 판정 → 혼란 자해 판정 → 기술 실행. (본가 순서: 혼란 → 마비 지만, 둘 다 걸린 경우 어느 쪽이 먼저든 결과 차이가 작아 구현 단순한 쪽 — **빌더 재량**.)
- **타입 면역** (4세대): 불꽃 → 화상 ✕, 얼음 → 얼음 ✕, 독·강철 → 독/맹독 ✕. 전기자석파는 기술 타입(전기) 상성상 땅 타입에 무효. 그 외 변화기는 상성을 보지 않음(랭크 스펙과 동일). 공격기 부가효과는 면역(상성 0)이면 애초에 발동 안 함.
- 변화기 명중 판정은 랭크 변화기와 같다(적 대상만, 회피 랭크·지형 회피 포함).
- 부가효과 발동 조건도 랭크 부가효과와 같다: 맞음 ∧ 면역 아님 ∧ 대상 기절 안 함, 확률 `ailmentChance`. 한 기술에 랭크·상태이상 부가효과가 둘 다 있으면 각각 따로 굴림.
- **상태 데미지로 기절**: 일반 기절과 같이 처리(유닛 제거, 아군이면 `log.fainted`, 결과 판정). 적이 상태 데미지로 쓰러지면 **살아 있는 아군 전원이 공유 비율(shareRatio)만큼** 경험치, 격파 코인은 정상 지급 — 쓰러뜨린 "주인"을 추적하지 않는다 (내 결정: 단순함). **혼란 자해로 적이 기절**해도 같은 규칙 (내 결정). `endPhase` 는 얼음·잠듦 판정용 `rng` 를 받는다.
- 층이 끝나면 전부 회복: 유닛이 층마다 새로 만들어지므로 자동. 저장 형식 변경 없음.
- 랭크 만료와 상태 데미지가 같은 페이즈 끝에 겹치면: 데미지 먼저, 그다음 랭크 만료 (기절한 유닛의 만료 알림은 안 나옴).

## 3-1. 시작 기술 구성 (사용자 결정)

`startingMoves` 는 최근 4개 중 **변화기(랭크·상태이상 포함) 최대 2개**, 나머지는 그 레벨까지 배운 가장 최근 공격기로 채운다 (공격기가 모자라면 있는 만큼, 공격기가 0 이면 기존 대로 몸통박치기). 레벨업 습득은 지금처럼 자유. 적 생성·뽑기 동료·새 게임 모두 이 함수를 쓰므로 함께 적용.

## 4. 적 AI

- 자신이 잠듦·얼음으로 쉬는 페이즈: 계획 없이 넘어감(대사만).
- 마비: `reachable` 이 절반 이동력을 쓰므로 자동 반영. 25% 실패는 실행 시 판정(계획엔 반영 안 함).
- 혼란: 계획은 그대로(자해 확률은 무시).
- 상태이상 기술 점수 (`positionalStatus` 에 추가, 명중 기대 반영, 이미 주 상태이상·면역·이미 혼란인 대상은 0):
  - 잠듦·얼음: 대상의 "아군에게 줄 최선 기대 데미지" × 1.5 (약 1~2턴 봉쇄)
  - 마비: 그 값 × 0.5 (실패 25% + 이동력 감소)
  - 화상: 대상이 물리형이면 그 값 × 0.5, 아니면 0.2 + 지속 데미지(최대 HP 1/8 × 2)
  - 독/맹독: 최대 HP 1/8 × 3 / 맹독 1/16 × 6
  - 혼란: 그 값 × 0.4
- **안티 목표 장치**: 이미 주 상태이상이 있는 대상은 점수 0 이므로 같은 대상에 연타 안 함. 잠듦 1~3턴, 얼음 최대 3턴이라 영구 봉쇄 없음. **상대 편(아군)이 이미 2마리 이상 잠듦·얼음이면 적 AI 는 잠듦 기술 점수 0** (사용자 결정; 계획 시점의 실제 상태로 판정하므로 같은 페이즈에 앞선 적이 재운 것도 반영됨).
- 아군 위협 계산(threatMap)은 변화기와 마찬가지로 상태이상 기술을 무시.

## 5. 화면

- **정보창**: 이름 옆에 상태 배지(본가 색: 마비 노랑 `마비`, 화상 주황 `화상`, 독 보라 `독`, 맹독 진보라 `맹독`, 잠듦 회색 `잠듦`, 얼음 하늘 `얼음`) + 혼란은 랭크 줄 앞에 `혼란` 표시.
- **맵**: 유닛 발밑 그림자 옆에 작은 상태 색 점(4×4). 잠듦·얼음 유닛은 Sleep 포즈가 있으면 Sleep, 없으면 회색 정지.
- **기술 메뉴·정보창**: 상태이상 변화기도 "변화" 태그, 효과 요약에 "마비" "잠듦" 등. 공격기 정보창에는 부가효과가 있으면 "화상 10%" 한 줄.
- **연출**: 랭크 팝업과 같은 방식으로 대상 위에 상태 배지 팝업 + 대사:
  - 걸림: "○○는 마비되어 기술이 나오기 어려워졌다!", "○○는 화상을 입었다!", "○○는 독에 걸렸다!", "○○는 맹독에 걸렸다!", "○○는 잠들어 버렸다!", "○○는 얼어붙었다!", "○○는 혼란에 빠졌다!"
  - 실패: "○○에게는 효과가 없는 것 같다..." (면역·이미 상태이상)
  - 행동 시: "몸이 저려서 움직일 수 없다!", "○○는 혼란스러워 한다!" → "영문도 모르고 자신을 공격했다!"
  - 페이즈 시작: "○○는 쿨쿨 잠들어 있다", "○○는 눈을 떴다!", "○○는 얼어 버려서 움직일 수 없다!", "○○의 얼음이 녹았다!"
  - 페이즈 끝: "○○는 독의 데미지를 입었다!", "○○는 화상 데미지를 입었다!", "○○의 혼란이 풀렸다!" (HP 바 감소 표시)
- 페이즈 시작·끝 대사는 랭크 만료 알림과 같은 `noticeChain` 으로, 배너 직후 한 건씩.
- 잠듦·얼음으로 쉬는 아군은 그 페이즈 시작부터 회색(acted), 선택 불가.

## 6. 아키텍처

```
tools/fetch-pokeapi.js   ailment, ailmentChance, toxic 구분; learnable 확장 → 재생성
src/data/moves.js        (변화 없음 — kind·range 규칙 재사용)
src/core/status.js       (신규, 순수) 걸기·면역·이동력·스피드 배율·페이즈 시작/끝 처리·자해 데미지
src/core/stages.js       effectiveStat 의 spe 에 마비 배율 (또는 status.js 에서 감싸기 — 빌더 재량)
src/core/damage.js       화상 물리 ×0.5, 혼란 자해 데미지 함수
src/core/pathfind.js     reachable 이동력에 마비 반영
src/core/battle.js       applyMove: 변화기 상태이상, 부가효과, 마비 실패·혼란 자해 판정, 불꽃 해동;
                         endPhase: 끝나는 편 상태 데미지·혼란 감소, 시작하는 편 잠듦·얼음 처리;
                         state.log.statusEvents = [{ unitId, kind, … }] (페이즈마다 새로)
src/core/ai.js           상태이상 점수, 쉬는 유닛 건너뜀
src/game/states.js       쉬는 유닛 처리, 이벤트 대사, 메뉴 정보
src/render/mapAttack.js  상태 팝업·대사, 실패/자해 연출
src/render/ui.js         상태 배지, 맵 점
```

`applyMove` 결과에 `statusChanges: [{ unitId, ailment, applied: boolean, reason?: 'immune'|'already' }]`, `blocked?: 'paralysis'|'confusion'`(마비 실패·자해로 기술이 안 나감), `selfHit?: { damage, fainted }`, `thawed?: unitId[]` 추가.
