# 성장 루프: 레벨업 · 기술 습득 · 진화 — 설계 스펙

- 작성일: 2026-11-12
- 상태: 사용자 리뷰 대기 (설계 대화에서 결정 사항 승인됨)
- 선행: `2026-11-12-pokemon-srpg-demo-design.md`, 마을 로비(b4ab022)

## 1. 목표

전투에서 쌓은 경험치로 포켓몬이 성장하고, PokeAPI 4세대(Pt) 습득표대로 기술을 배우며, 정해진 규칙대로 진화한다.
진행 상황은 브라우저에 저장되어 다시 출격할 이유가 생긴다.

### 성공 기준
1. 아군·적 모두 1단계 포켓몬으로 시작하고, 능력치는 레벨에 따라 계산된다.
2. 적을 쓰러뜨리면 경험치를 얻고, 전투 후 결산 화면에서 레벨업 → 기술 습득(4개 초과 시 잊을 기술 선택) → 진화가 순서대로 처리된다.
3. 진화 조건은 §4 규칙(원작 레벨 / 대체 레벨 매트릭스 / 진화의돌)을 따른다.
4. 진화의돌은 스테이지 첫 클리어 보상으로 받고, 마을 편성소에서 쓴다.
5. 새로고침해도 파티(레벨·경험치·기술)·클리어 기록·아이템이 유지된다.
6. 포켓몬·기술 데이터는 스크립트로 PokeAPI 에서 한 번 받아 저장한 파일을 쓴다 (실행 중 API 호출 없음).
7. `npm test` 통과, 브라우저에서 출격 → 결산 → 진화 → 마을 → 저장/불러오기 흐름이 동작.

### 범위 밖 (YAGNI)
변화기·능력치 랭크·상태이상(습득표의 변화기는 건너뜀), 위력이 고정되지 않은 기술(카운터·용의분노 등, power=null), 진화 취소(B 버튼), 기술 다시 떠올리기, 동료 영입·교체, 특성·성격·개체값 변동, 다른 아이템.

## 3. 데이터 파이프라인 (PokeAPI)

`tools/fetch-pokeapi.js` 를 실행하면 `src/data/generated/pokedex.js` 를 만든다 (ES 모듈 `export default {...}`, 저장소에 커밋). 게임 실행 중에는 API 를 호출하지 않는다.

- 대상: §2 의 24종 (도구 상단 목록, 추가 가능)
- 종족: `api`, `dex`, 한국어 이름, 타입(`past_types` 에 4세대 값이 있으면 그것), 종족값 6개, `base_experience`, 성장 곡선(`growth_rate`), 진화(다음 단계 + 원본 조건)
- 습득표: version group **platinum** 의 `level-up` 기술만 (레벨, 기술 api)
- 기술: 습득표에 나오는 기술 전부의 한국어 이름·타입·물리/특수/변화·위력·명중. `power === null` 이거나 `damage_class === status` 인 기술은 `learnable: false` 로 표시해 습득에서 건너뛴다.
- 받은 원본 진화 조건을 §4 규칙으로 **분류한 결과**(`evolution.rule`)도 함께 저장한다. 분류 함수는 `src/core/evolution.js` 의 순수 함수로 두고 도구와 테스트가 같이 쓴다.
- 기존 손으로 쓴 `moves.js`·`species.js` 는 생성 데이터로 대체한다. 데이터가 PokeAPI 에서 직접 오므로 `tools/check-pokeapi.js` 는 삭제한다. 기존 20개 기술의 사거리 등 **SRPG 전용 값은 `src/data/moveRanges.js`** 에 남긴다.

### 3.1 사거리 규칙 (PokeAPI 에 없음)
- 기본: 물리 `[1,1]`, 특수 `[1,2]`
- 예외는 `moveRanges.js` 에 기술 api 로 지정 (기존: 파동탄·섀도볼 `[2,3]`, 잎날가르기 `[1,2]` 등 기존 값 유지)

### 3.2 이동력 규칙 (종족값 스피드 기준)
`< 50 → 3`, `< 80 → 4`, `< 100 → 5`, 그 외 `6`. 비행 타입은 +1 (최대 6).

## 4. 진화 규칙

원본 조건을 다음 순서로 분류한다 (`classifyEvolution(details, lineInfo)`):

1. **돌**: 트리거가 `use-item` → `{ kind: 'stone' }` (어떤 돌이든 '진화의돌' 1개)
2. **원작 레벨**: `level-up` 이고 `min_level` 외 다른 조건이 없음 → `{ kind: 'level', level: min_level }`
3. **대체 레벨**: 그 외 (`min_happiness` = 친밀도, `trade` = 교환, 기술·장소·시간·성별 등 = 기타) → 아래 매트릭스

| 계열 | 진화 순번 | 친밀도 | 교환 | 기타 |
|---|---|---|---|---|
| 2단 계열 | 유일한 진화 | 20 | 30 | 25 |
| 3단 계열 | 1차 | 16 | 20 | 18 |
| 3단 계열 | 2차 | 32 | 36 | 34 |

- **보정**: 3단 계열 2차의 레벨이 (1차 진화 레벨 + 8) 보다 낮으면 1차 + 8 로 올린다. 1차가 돌 진화면 보정하지 않는다.
- 한 단계에 원본 조건이 여러 개면 위 1→2→3 순서로 먼저 맞는 것 하나를 쓴다.
- 매트릭스는 `src/data/balance.js` 의 값으로 두어 숫자만 바꿀 수 있게 한다.

검증된 결과 (PokeAPI 조회, 2026-11-12):
불꽃숭이 L14 → L36 · 팽도리 L16 → L36 · 모부기 L18 → L32 · 꼬링크 L15 → L30 · 리올루 친밀도→**L20** · 딥상어동 L24 → L48 · 니로우 **돌** · 꼬몽울 친밀도→**L16** → 로젤리아 **돌** · 동미러 L33

## 5. 레벨 · 능력치 · 경험치

### 5.1 능력치
개체값 31, 노력치 0, 성격 무보정 (기존 Lv50 근사와 같은 기준):
- HP = `floor((2B + 31) × L / 100) + L + 10`
- 그 외 = `floor((2B + 31) × L / 100) + 5`

레벨업·진화 시 최대 HP 가 늘어난 만큼 현재 HP 도 늘린다 (전투 밖에서는 항상 풀 HP 로 출격).

### 5.2 데미지
기존 공식의 레벨 50 고정값을 **공격자의 레벨**로 바꾼다: `(2 × L / 5 + 2)`.

### 5.3 경험치
- 쓰러뜨린 적 1마리당: `floor(base_experience × 적 레벨 / 7) × 배율` (배율 기본 2, `balance.js`)
- 분배는 **적을 쓰러뜨린 그 순간** 기준: 쓰러뜨린 아군 100%, 그 순간 살아 있는 다른 아군 각 50%
- 나중에 기절한 아군도 이미 받은 몫은 그대로 가진다 (기절 이후 몫은 없음)
- 패배해도 쌓은 경험치는 받는다. 진화의돌 보상은 승리 시에만.
- 레벨 곡선: PokeAPI `growth_rate` 6종(fast, medium, medium-slow, slow, erratic, fluctuating)의 원작 공식. 최대 Lv.100.
- 전투 중: 적을 쓰러뜨린 순간 공격자 위에 `+N EXP` 표시만 한다. 레벨업 처리는 결산에서.

## 6. 기술 습득

- 레벨이 L 에서 L' 로 오르면 (L, L'] 구간에서 배우는 `learnable` 기술을 레벨 순으로 처리한다.
- 이미 아는 기술은 건너뛴다. 기술이 4개 미만이면 바로 배운다.
- 4개면 결산 화면에서 "○○를 배우고 싶다… 기술을 잊게 할까?" → 잊을 기술 4개 + "배우지 않는다" 중 선택.
- 진화 직후에는 진화한 종족의 습득표에서 **현재 레벨과 같은 레벨**의 기술을 같은 방식으로 처리한다.
- 시작 기술(아군 생성·적 생성): 습득표에서 레벨 이하의 `learnable` 기술 중 **최근 4개**. 하나도 없으면 몸통박치기(`tackle`).

## 7. 화면 흐름

```
전투 결과 → [결산] → (진화 연출 × N) → 마을 → 자동 저장
마을 편성소 → [편성] → 진화의돌 사용 → 진화 연출 → 저장
타이틀 → [이어하기 | 처음부터]
```

### 7.1 결산 화면 (`src/game/results.js`)
- 상단: "승리!" / "패배…", 첫 클리어면 "진화의돌을 얻었다!"
- 아군 4줄: 초상화 · 이름 · Lv · 경험치 바. 바가 차오르는 연출 (Z 로 즉시 완료).
- 레벨업 시 해당 줄에 "Lv.9 ▶ 10" 과 능력치 증가 요약.
- 기술 습득 선택은 대사창 + 메뉴 (§6).
- 끝나면 진화 대상 목록을 진화 연출 장면에 넘긴다.

### 7.2 진화 연출 (`src/game/evolution.js`)
- 대사 "어라…? ○○의 모습이…!" → 두 종족 스프라이트가 번갈아 깜빡이며 점점 빨라짐(약 2.5초) → 흰 번쩍임 → "축하합니다! ○○는 △△로 진화했다!" → 진화 후 습득 기술 처리.
- 취소 없음.

### 7.3 편성 화면 (`src/game/party.js`, 마을 '편성소' 표지판)
- 아군 목록: 초상화 · 이름 · Lv · 다음 레벨까지 경험치 · 기술 4개 · 진화 조건 안내 ("Lv.14에 진화", "진화의돌로 진화", "최종 진화").
- 메뉴: "진화의돌 사용 (n개)" — 대상이 있으면 선택해서 진화, 없으면 안내 대사.
- X 로 마을 복귀.

### 7.4 타이틀
저장이 있으면 [이어하기 / 처음부터], 없으면 [처음부터]. "처음부터"를 저장이 있는 상태에서 고르면 확인 대사 후 덮어쓴다.

## 8. 저장

- `localStorage` 키 `pokemon-tactics-save`, JSON:
  `{ version: 1, party: [{ species, level, exp, moves: [api…] }], cleared: [stageId…], items: { evoStone: n } }`
- 저장 시점: 결산·진화 종료 후, 편성소에서 진화한 뒤, "처음부터" 시작 직후.
- 읽기 실패·형식 불일치·접근 예외 시 저장 없음으로 취급 (콘솔 경고 1회). 저장 실패는 게임을 멈추지 않는다.
- 저장 데이터의 종족·기술이 생성 데이터에 없으면 그 항목을 건너뛰고 기본값으로 보충한다.

## 9. 아키텍처 변경

```
tools/fetch-pokeapi.js        PokeAPI → src/data/generated/pokedex.js
src/data/generated/pokedex.js 생성 데이터 (커밋)
src/data/balance.js           진화 매트릭스, 경험치 배율, 시작 레벨, 보정 +8
src/data/moveRanges.js        SRPG 사거리 예외
src/data/species.js           생성 데이터 → SPECIES (이동력 규칙 적용), 기존 API 유지
src/data/moves.js             생성 데이터 → MOVES (사거리 규칙 적용), 기존 API 유지
src/core/stats.js             능력치·레벨 곡선·경험치 계산 (순수)
src/core/evolution.js         진화 분류·판정 (순수)
src/core/learn.js             시작 기술, 레벨 구간 습득 목록 (순수)
src/core/progress.js          파티 상태 갱신: 경험치 적용 → 레벨업 이벤트 목록 (순수)
src/core/save.js              직렬화/검증 (순수) + storage 어댑터 주입
src/core/battle.js            유닛에 level·stats·moves, 경험치 기록
src/core/damage.js, ai.js     SPECIES 고정 능력치·기술 대신 유닛 값 사용
src/game/results.js, evolution.js, party.js   새 장면
src/game/title.js, town.js, main.js            메뉴·편성소 연결·저장
```

- `core/` 는 여전히 DOM 을 모른다. `save.js` 는 `{ getItem, setItem }` 를 주입받아 테스트에서 메모리 저장소를 쓴다.
- 전투 `onExit(result, log)` 의 `log` = `{ exp: { [unitId]: n }, firstClear: bool }`.

## 10. 오류 처리

- 생성 데이터에 필요한 종족이 없으면 `validateData()` 가 시작 시 오류를 던진다.
- 스프라이트가 없는 새 종족은 기존처럼 임시 도트로 그린다.
- `fetch-pokeapi.js` 는 실패한 요청을 재시도 1회 후 종료 코드 1 로 끝내고, 기존 생성 파일을 덮어쓰지 않는다.
