- 작성일: 2026-11-13
- 상태: 사용자 리뷰 대기 (설계 질문 답변 반영)
- 선행: 성장 루프(`2026-11-12-growth-evolution-design.md`), main `de6d3c0`

## 1. 목표

고정 스테이지 대신, **매번 자동 생성되는 층을 내려가는 던전**을 탐험한다. 한 던전을 끝까지 클리어하면 다음 종류의 던전이 열린다.

### 성공 기준
1. 마을 출격 게시판에서 던전을 고르면 1층부터 탐험이 시작되고, 층마다 지형·적 배치가 달라진다.
2. 층 클리어: **아군 1마리가 계단에 도달**하거나 **적 전멸**. 마지막 층(보스 층)은 **보스를 쓰러뜨리면** 클리어.
3. 층 사이: 결산(경험치·레벨업·기술·진화) → [다음 층으로 / 마을로 돌아가기] 선택.
4. HP: 매 층 완전 회복. 단 그 층에서 기절한 포켓몬은 다음 층을 **최대 HP 50%** 로 시작.
5. 전멸: 레벨·기술은 유지, **이번 탐험에서 보물상자로 얻은 것만 잃는다**. 마을로 복귀.
6. 마지막 층 클리어 → 탐험 보상 확정, 다음 던전 해금.
7. 새 층에 들어갈 때마다 저장. 도중에 꺼도 "이어하기"로 그 층 처음부터 **같은 맵**으로 재개.
8. `npm test` 통과, 브라우저에서 던전 선택 → 여러 층 → 보스 → 해금 → 저장/재개 흐름 동작.

### 범위 밖 (YAGNI)
방+통로형 맵, 층마다 보상 3택 1, 상점·아이템 사용, 동료 영입, 함정·날씨, 3번째 이후 던전, 던전 안 무작위 이벤트, 출전 멤버 선택(파티 4마리 전원 출전 유지).

## 2. 던전

`src/data/dungeons.js`

| id | 이름 | 층 | 해금 조건 | 테마 | 적 레벨 (층 f) | 적 수 | 적 풀 (등장 최소 층) | 보스 |
|---|---|---|---|---|---|---|---|---|
| `sinnoh-field` | 신오 들판 | 5 | 처음부터 | field | `7 + f` | `min(3 + ceil(f/2), 6)` | 꼬몽울 1 · 니로우 1 · 리오르 2 · 딥상어동 3 · 동미러 3 | 5층: 리오르 Lv.`7+5+3` |
| `sinnoh-cave` | 신오 동굴 | 7 | 신오 들판 클리어 | cave | `12 + f` | `min(4 + ceil(f/2), 6)` | 동미러 1 · 딥상어동 1 · 로젤리아 2 · 니로우 3 · 한바이트 5 | 7층: 한바이트 Lv.`12+7+3` |

- 적 종류는 그 층에서 등장 가능한 풀에서 무작위 (같은 종류 중복 허용).
- 보스는 보스 층의 적 구성에 **추가**되며, 정보창·대사에 "보스" 표시. 보스 층에는 계단이 없다.
- 적은 진화하지 않는다. 보스·동굴 일부(로젤리아·한바이트)는 2단계 종족 (생성 데이터 24종 안에서).
- 던전 표는 데이터 파일 하나로 두어 숫자만 바꾸면 된다.

## 3. 층 맵 생성 (지형 덩어리)

`src/core/floorgen.js` — **순수 함수** `generateFloor(dungeon, floor, seed) => FloorMap`. 같은 입력이면 항상 같은 결과.

- 크기 16×12 (현재 맵과 동일, 카메라 스크롤 그대로).
- 타일 기호는 기존과 같다: `.` 바닥 · `"` 은폐(회피+15%) · `^` 고지(이동 2, 방어×1.2) · `~` 물 · `#` 벽. 새 기호 `>` **계단**(이동 1, 효과 없음).
- 절차:
  1. 전부 `.` 로 채움.
  2. 테마별 덩어리 개수만큼 무작위 걸음(random walk, 길이 4~12)으로 `"` `^` `~` `#` 를 칠함. (field: 수풀 3·바위 2·물 1~2·나무 2 / cave: 은폐 2·고지 3·물 1·벽 4)
  3. **연결성 보장**: 아군 출발 칸에서 땅 타입 기준(물·벽 불가)으로 BFS. 도달 못 한 바닥 칸이 있으면, 그 칸에서 가장 가까운 도달 칸까지 막힌 칸을 `.` 로 뚫는다. 반복.
  4. 아군 출발 4칸: 왼쪽 3열 안의 바닥 칸. 적: 오른쪽 절반의 바닥 칸, 서로 다른 칸.
  5. 계단(보스 층 제외): 아군 출발 칸에서 BFS 거리가 가장 먼 바닥 칸 상위 25% 중 무작위.
  6. 보물상자 0~2개: 도달 가능한 바닥 칸 무작위 (확률: 0개 30% · 1개 50% · 2개 20%).
- 반환: `{ tiles: string[], allySlots: [{x,y}×4], enemies: [{species, level, x, y, boss?}], stairs: {x,y}|null, chests: [{x,y}] }` — 기존 `createBattle(mapDef, party)` 가 그대로 받는 형태 + `stairs`, `chests`.
- 시드: 탐험 시작 시 하나 정하고, 층 시드 = `hash(runSeed, floor)`. 기존 `core/rng.js` 의 `createRng` 사용.

### 3.1 테마 (그리기만 다름)
`render/tiles.js` 가 `theme` 를 받는다. field = 지금 타일. cave = 바닥 회갈색, 은폐 = 수정 조각, 고지 = 석순, 물 = 지하수, 벽 = 동굴 벽. 계단 = 두 테마 공통 도트(아래로 내려가는 계단). 보물상자 = 맵 위 오브젝트(나무 상자 도트), 열리면 사라짐.

## 4. 전투 규칙 추가

- **계단**: 아군이 이동을 마친 칸이 계단이면 그 행동이 끝나는 즉시 층 클리어(`state.result = 'stairs'`). 적은 계단을 목표로 하지 않는다(AI 변경 없음, 지나가는 것은 가능).
- **보스 층**: 보스가 쓰러지면 `result = 'win'` (남은 적은 무시).
- **보물상자**: 아군이 이동을 마친 칸에 상자가 있으면 열린다 → 대사 "보물상자를 열었다! ○○을/를 얻었다!" → 탐험 보상에 추가. 적은 열지 않는다.
  - 내용: 진화의돌 20%, 경험 사탕 80%. 경험 사탕 1개 = 파티 전원에게 `floor × 30` 경험치 (탐험 성공 또는 귀환 시 지급).
- 기존 승패: 적 전멸 = `win`, 아군 전멸 = `lose`.
- 출격 HP: `createBattle` 이 멤버별 시작 HP 비율(`hpRatio`, 기본 1)을 받는다.

## 5. 탐험(런) 흐름

`src/core/run.js` — 순수 함수로 탐험 상태 관리.

```
Run = { dungeonId, floor, seed, faintedLast: string[] /*종족*/, loot: { evoStone, candy } }
```

- `startRun(dungeonId, seed) => Run` (floor 1, loot 0)
- `floorStartHp(run, party) => { [species]: 0.5 | 1 }` — `faintedLast` 에 있으면 0.5
- `afterFloor(run, battleResult, fainted) => { run, outcome }`
  - `stairs` / `win`(보스 아님) → 다음 층 준비 (`floor+1`, `faintedLast = fainted`), outcome `'next'`
  - 보스 층 `win` → outcome `'cleared'`
  - `lose` → outcome `'wiped'`
- `addLoot(run, item)`, `settleLoot(game, run)` — 성공·귀환 시 진화의돌은 `game.items` 로, 경험 사탕은 경험치로 지급. 전멸이면 아무것도 지급하지 않음.

장면 흐름 (`main.js`):

```
게시판 → 던전 선택 → [층 시작: 저장 + 배너 "신오 들판 B1F"] → 전투
  → 결산(경험치·레벨업·기술·진화)
  → next: [다음 층으로 | 마을로 돌아가기]  → 다음 층 시작 / 귀환(보상 지급)
  → cleared: "신오 들판을 돌파했다!" + 보상 지급 + 해금 안내 → 마을
  → wiped: "눈앞이 캄캄해졌다…" (보물 잃음, 경험치는 유지) → 마을
```

- 던전 선택 화면은 기존 스테이지 선택을 바꾼 것: 이름, 층 수, 최고 기록(최대 도달 층), 잠김이면 해금 조건 표시.
- 진행 중인 탐험(`run`)이 있으면 목록 맨 위에 "탐험 이어하기 (신오 들판 B3F)" 가 나오고, 다른 던전을 고르면 "진행 중인 탐험을 포기할까?" 확인 후 새로 시작한다 (포기 = 전멸과 같이 보물 잃음).
- 결산은 기존 `createResults` 를 그대로 쓰고, 첫 클리어 진화의돌 지급(`firstClear`) 대신 탐험 보상으로 처리한다.

## 6. 저장

- `GameState` version **2**:
  `{ version: 2, party, items: { evoStone }, unlocked: string[], best: { [dungeonId]: maxFloor }, cleared: string[], run: Run | null }`
- 저장 시점: 층 시작 직전(run 포함), 탐험 종료 후(run = null), 편성소 진화 후.
- 타이틀 "이어하기": `run` 이 있으면 "탐험을 이어서 할까?" → 예: 그 층 시작으로(같은 시드라 같은 맵), 아니요: 마을(탐험은 그대로 남음, 게시판에서 다시 이어하기 가능).
- **v1 → v2 이전**: party·items 유지, `unlocked = ['sinnoh-field']`, `best = {}`, `cleared = []`, `run = null`. 기존 v1 `cleared` 의 `sinnoh-field` 는 고정 스테이지 기록이라 버린다.
- 그 밖의 처리 규칙(깨진 데이터, 프로토타입 키 등)은 기존 `save.js` 를 따른다.
