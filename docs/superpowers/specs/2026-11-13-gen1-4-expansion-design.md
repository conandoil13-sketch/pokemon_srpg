# 포켓몬 1~4세대 확장 + 메타몽 주인공 — 설계 스펙 (A)

- 작성일: 2026-11-13
- 상태: 사용자 리뷰 대기
- 선행: 로그라이크 던전(main `1d2d6f2`)
- 후속(별도 스펙 B): 뽑기 동료 해금 + 출전 편성. 이번 스펙은 B 가 쓸 데이터를 준비하지만 뽑기·편성 자체는 다루지 않는다.

## 1. 목표

포켓몬을 1~4세대 493종으로 늘려 던전 적으로 등장시키고, 갈래가 있는 진화를 지원하며, 메타몽을 주인공으로 세운다.

### 성공 기준
1. 생성 데이터에 전국도감 1~493번 전부(기본 폼)가 들어 있고, 4세대 기준 타입·습득표·기술 값을 쓴다.
2. 던전 적은 테마 타입에 맞는 종족 중에서 층 깊이에 따라 진화 단계가 올라가며 무작위로 나온다. 전설·환상 포켓몬은 나오지 않는다.
3. 진화 갈래: 조건을 만족하는 갈래가 둘 이상이면 **플레이어가 고른다**. 원작에서 무작위인 진화(개무소)는 **무작위**.
4. 메타몽이 주인공: 마을에서 걷는 리더이고, 전투에 항상 출전하는 5번째 멤버다 (기술: 몸통박치기, 변신은 이후 확장).
5. 스프라이트는 화면에 나오는 종족만 필요할 때 불러온다. 시작할 때 493종을 한꺼번에 불러오지 않는다.
6. 기존 저장은 메타몽이 파티 맨 앞에 추가된 채로 이어진다.
7. `npm test` 통과, 브라우저에서 여러 테마의 다양한 적·메타몽 출전·분기 진화 선택이 동작.

### 범위 밖
뽑기·동료 영입·출전 편성(스펙 B), 변신 기능, 폼 체인지(데옥시스·로토무 등은 기본 폼만), 성별·특성·도구, 5세대 이후.

## 2. 데이터 파이프라인 확장

`tools/fetch-pokeapi.js`
- 대상: 전국도감 1~493 (목록을 손으로 쓰지 않고 번호 범위로).
- 습득표: version group `platinum` 의 level-up. 비어 있으면 `heartgold-soulsilver`, 그다음 `diamond-pearl` 순으로 대체.
- 종족 필드 추가: `stage`(진화 단계 0·1·2), `bst`(종족값 합), `legendary`(`is_legendary || is_mythical`), `evolutions`(아래 §3, 기존 `evolution` 대체).
- 동시 요청 8개 제한, 응답은 `tools/.cache/`(git 제외)에 저장해서 다시 실행할 때 재사용. 실패 시 기존 생성 파일을 덮어쓰지 않는다(기존 규칙 유지).
- 출력: `src/data/generated/pokedex.js` 하나 (예상 수백 KB). 결정적 정렬 유지.

## 3. 분기 진화

`evolutions: [{ to, rule }]` (최종형은 빈 배열). 각 갈래의 `rule` 은 기존 분류(`classifyEvolution`)를 그 갈래 경로 기준(계열 단수·순번·이전 레벨)으로 계산한다. 갈래별로 다음을 추가한다.

- **무작위 묶음**: 같은 출발 종족의 갈래 중 둘 이상이 **같은 원작 레벨 조건만** 가진 경우 (예: 개무소 → 실쿤/카스쿤, Lv.7) → 그 갈래들의 `rule.random = true`.
- 성별·능력치 비교·장소·기술 등 레벨 외 조건은 기존처럼 "기타" 대체 레벨이 된다 (예: 배루키 → 시라소몬/홍수몬/카포에라 모두 Lv.25 → 선택).
- 돌 갈래가 여럿이면 진화의돌을 쓸 때 고른다 (예: 이브이 → 샤미드/쥬피썬더/부스터).
- 이브이의 나머지 갈래: 에브이·블래키(친밀도) → Lv.20 에서 둘 중 선택, 리피아·글레이시아(장소) → Lv.25 에서 선택(그때까지 진화하지 않았다면).
- 494번 이후 종족으로 가는 갈래(예: 이브이 → 님피아)는 데이터에서 뺀다.

처리 규칙 (`core/evolution.js`, `core/progress.js`):
- `levelEvolutionOptions(species, level) => to[]` — 레벨 조건을 만족하는 갈래들.
- 결산에서 레벨업 후: 옵션 0개 → 없음 / 1개 → 그대로 / 여럿이고 모두 `random` → 시드 RNG 로 하나 / 그 외 → **선택 창** "어느 모습으로 진화할까?" + [각 갈래 이름…, 진화하지 않는다].
- 진화하지 않기를 고르면 다음 레벨업 때 다시 묻는다.
- 편성소 진화의돌: 돌 갈래가 여럿이면 같은 선택 창.

## 4. 던전 적 구성

`src/data/dungeons.js` 의 고정 `pool` 대신 **규칙**으로 고른다 (`core/encounters.js`, 순수).

| 던전 | 테마 타입 | 종족값 합 상한 | 진화 단계 상한 (층 f) |
|---|---|---|---|
| 신오 들판 | 노말·풀·벌레·비행·전기·페어리 | 420 | f ≤ 2: 0단계 · f ≤ 4: 1단계 · 보스층: 2단계 |
| 신오 동굴 | 바위·땅·강철·고스트·독·드래곤·격투 | 470 | f ≤ 3: 0단계 · f ≤ 6: 1단계 · 보스층: 2단계 |

- 후보 = 테마 타입이 하나라도 겹침 ∧ `!legendary` ∧ `stage ≤ 상한` ∧ `bst ≤ 상한`(보스는 상한 +80) ∧ 메타몽 제외.
- 층마다 시드 RNG 로 후보 중 무작위 (중복 허용). 보스 = 보스층 상한 단계 후보 중 무작위 1마리, 레벨 +3.
- 후보가 비면 상한을 한 단계씩 올려 다시 찾는다 (데이터 테스트에서 비지 않음을 확인).
- 4세대 타입 기준(예: 삐삐는 노말)으로 판정.

## 5. 메타몽 주인공

- 파티 = `[메타몽, 불꽃숭이, 팽도리, 모부기, 꼬링크]`. 메타몽은 다른 멤버처럼 레벨·경험치를 가진다 (시작 Lv.8, 기술 몸통박치기).
- 마을 리더는 항상 메타몽 (파티 첫 멤버 규칙 그대로).
- 전투: 아군 출발 칸 5개 (생성기 `allySlots` 4 → 5, 왼쪽 3열 안). 메타몽도 일반 유닛과 같다.
- 메타몽이 기절해도 전투는 계속, 아군 전멸 규칙은 그대로.
- 변신(`transform`)은 변화기라 지금은 배우지 않는다. 이후 확장 때 메타몽 전용 처리로 붙인다.

## 6. 스프라이트 지연 로딩

`render/sprites.js`
- `requestSprites(keys)`: 아직 요청하지 않은 종족만 불러오기 시작 (Promise 반환, 실패는 조용히 폴백).
- 로딩 중·실패한 종족은 지금처럼 임시 도트로 그린다 (깜빡이지 않게, 로드되면 다음 프레임부터 교체).
- 호출 시점: 타이틀 이후 파티 종족, 층 생성 직후 그 층의 적 종족, 진화 연출 직전 진화 후 종족, 편성소 진입 시.
- 시작 시 `loadSprites(전체)` 는 제거.

## 7. 저장

- version 3. v2 → v3: 파티 맨 앞에 메타몽이 없으면 `newMember('ditto')` 를 넣는다. 나머지 유지. v1 은 기존대로 v2 를 거쳐 v3 로.
- 멤버의 종족은 493종 전체에서 검증 (기존 규칙).

## 9. 테스트

- `data.test.js`: 493종, 메타몽 존재, 모든 종족 시작 기술 ≥ 1, 이브이 돌 갈래 3 + 대체 레벨 갈래, 개무소 갈래 `random`, 배루키 갈래 3개 같은 레벨, 삐삐 타입 노말(4세대).
- `encounters.test.js`: 두 던전 × 모든 층 후보가 비지 않음, 전설·메타몽 제외, 단계·종족값 상한, 테마 타입 겹침, 시드 결정성.
- `floorgen.test.js`: 기존 속성 검사를 새 적 선택·아군 5칸으로 갱신 (시드 300개).
- `evolution.test.js`/`progress.test.js`: 갈래 옵션 계산, 무작위 묶음, 선택 이벤트, 진화하지 않기 후 다음 레벨업에 재질문.

- `results.test.js`: 진화 선택 창 (연타 시 아무것도 고르지 않음 — 기존 확인창 규칙 재사용).
- 브라우저: 들판·동굴 여러 층에서 다양한 적, 메타몽 출전·마을 리더, 분기 진화 선택(배율을 올려 이브이를 넣어서), 네트워크 패널에서 시작 시 요청 수가 파티 종족 수준인지.
