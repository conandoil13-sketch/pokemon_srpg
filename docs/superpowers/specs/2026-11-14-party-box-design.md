# 편성소 박스 화면 — 설계 스펙

- 작성일: 2026-11-14 · 상태: 빌더 체크 완료, 사용자 승인 대기
- 대체: 지금 편성소(`src/game/party.js`, 한 줄씩 나열 + 메뉴 4개)

## 1. 목적 · 이유
동료가 뽑기로 수십 마리까지 늘고, 한 마리의 정보도 늘었다(특성·결정·기술·진화 조건). 한 줄씩 넘기는 목록으로는 찾기도 보기도 답답하다. **본가 PC 박스처럼** 아이콘 격자에서 훑어보고, 커서를 올리면 바로 핵심 정보, 필요하면 자세히 보기로 들어간다.

### 사용자 결정
- 박스 = 아이콘 격자 + 왼쪽 짧은 패널 + 아래 출전 줄. 자세한 정보는 **따로 "자세히 보기" 화면(A안)**.
- **특성은 결정으로 한 번 해금하면 그 뒤로 공짜로 바꿀 수 있다** (매번 소비가 아니라 해금 비용).
- 정렬은 **자동 정렬** (직접 옮기기·박스 이름 없음).
- 출전 표시는 **★ 이 아님** (★ 은 나중 이로치용으로 남김) → 파란 테두리 + 모서리 깃발.
- 만드는 방식: 새 박스 화면으로 교체 (1안). 정렬·특성 규칙은 순수 모듈, 저장 버전 올림.

### 성공 기준
1. 동료 30마리가 넘어도 박스를 넘기며 원하는 동료를 빨리 찾는다.
2. 커서를 올리면 이름·레벨·타입·특성·출전 여부가 바로 보인다.
3. 자세히 보기에서 정보·능력치·기술·특성 4페이지를 넘겨 본다.
4. 출전 넣기/빼기, 진화의돌, 특성 해금·바꾸기를 박스에서 한다 (지금 편성소 기능 모두).
5. 기존 저장을 불러와도 동료·출전·특성이 그대로.
6. `npm test` 통과, 브라우저로 화면 확인.

### 범위 밖 · 안티 목표
- 범위 밖: 아이콘 직접 옮기기, 박스 이름, 놓아주기, 기술 순서 바꾸기·잊기, 이로치, 숨겨진 특성.
- **안티 목표**: 작은 화면(256×192)에 글씨를 빽빽하게 넣어 읽기 힘들면 실패. 지금 편성소에서 되던 것(출전·진화의돌·특성)이 안 되면 실패. 저장을 불러왔더니 출전·특성이 바뀌면 실패.

## 2. 화면

### 2-1. 박스 (기본 화면)
```
┌──────────┬────────────────────────────┐
│[초상화]  │ ◀ 박스 1/2 ▶  정렬: 들어온 순│
│불꽃숭이  │ ▢▢▢▢▢▢                      │
│Lv.12     │ ▢▢▢▢▢▢   동료 아이콘 6×5     │
│[불꽃]    │ ▢▢▢▢▢▢   (한 박스 30칸)      │
│특성 맹화 │ ▢▢▢▢▢▢                      │
│출전 중   │ ▢▢▢▢▢▢                      │
├──────────┴────────────────────────────┤
│출전 [메타몽][불꽃숭이][팽도리][모부기][  ]│
└───────────────────────────────────────┘
```
- **격자**: 6열 × 5줄 = 30칸, 칸 약 24px. 아이콘은 초상화(`drawPortrait`)를 줄여 그리고, 초상화가 없으면 서 있는 스프라이트 첫 장면.
- **출전 표시**: 출전 중인 동료 칸은 파란 테두리 + 오른쪽 위 작은 깃발. 메타몽도 출전 표시.
- **박스 넘기기**: 격자 맨 왼쪽/오른쪽에서 좌우 이동 또는 머리줄 ◀ ▶ 클릭. 박스 수 = ⌈동료 수 / 30⌉ (최소 1).
- **정렬**: 머리줄 "정렬: …" 을 고르면(또는 단축 키) 들어온 순 → 레벨 순 → 도감 번호 순 순환. 정렬은 화면 상태만(저장하지 않음, 다음에 열면 들어온 순 — 빌더 재량으로 저장해도 됨).
- **왼쪽 패널**: 커서 칸의 초상화, 이름, Lv, 타입 배지, 특성 이름, "출전 중"/"대기".
- **아래 출전 줄**: 메타몽 + 출전 4자리. 커서를 이 줄로 내릴 수 있고, 거기서 확인하면 같은 메뉴.
- **조작**: 방향키·마우스(올리면 커서, 클릭 = 확인). 취소 = 마을로.

### 2-2. 동료 메뉴 (확인을 누르면)
- `출전에 넣기` / `출전에서 빼기` (메타몽은 항상 출전 — 빼기 없음, 기존 거절 대사 그대로: 꽉 참·마지막 1마리·메타몽)
- `자세히 보기`
- `진화의돌 (n개)` — 그 동료가 돌로 진화할 수 있을 때만 활성. 기존 진화 흐름(`onEvolve`) 그대로.
- `특성` → 자세히 보기의 특성 페이지로 바로
- `그만둔다`

### 2-3. 자세히 보기 (좌우로 4페이지, 위아래로 다른 동료, 취소 = 박스로)
| 페이지 | 내용 |
|---|---|
| 1 정보 | 초상화·이름·Lv·타입, 경험치 바와 다음 Lv 까지, 진화 조건(`evolutionHint`), 계열 결정 수, 출전 여부 |
| 2 능력치 | HP·공격·방어·특공·특방·스피드 (전투와 같은 `statsAt` 값, 막대 그래프), 이동력(종족 `move`) |
| 3 기술 | 기술 4개: 이름·타입 배지·분류(물리/특수/변화)·위력·명중·사거리·범위 모양 이름 |
| 4 특성 | 지금 특성 이름 + 설명. 특성이 둘인 종: 다른 특성 이름 + 설명과 상태 — 잠김(`해금 (결정 3)`, 결정 부족이면 비활성) 또는 해금됨(`이 특성으로 바꾸기`). 특성이 하나인 종: "특성은 하나뿐이다" |

- 긴 설명은 작은 글씨 줄바꿈(지금 `fitLines`), 넘치면 줄 수 제한.

## 3. 규칙 (순수 모듈)

### 3-1. 특성 해금
- 멤버에 `abilityUnlocked: boolean` (특성이 둘인 종만 의미). 잠김 = 지금 슬롯의 특성만, 해금 = 두 특성 모두. 새로 들어온 동료는 무작위 슬롯 + 잠김. 해금 = 계열 뿌리(`lineRoot`) 결정 **3개** 1회 소비(`ABILITY_UNLOCK_COST = 3`, 지금 `ABILITY_SWAP_COST` 대체).
- 해금된 멤버는 `setAbilitySlot(game, species, slot)` 로 공짜 전환. 진화해도 `abilityUnlocked`·슬롯 유지.
- 함수: `unlockAbility(game, species) => {ok} | {ok:false, reason:'missing'|'single'|'already'|'shards'}`, `setAbilitySlot(game, species, slot) => {ok} | {ok:false, reason:'missing'|'locked'|'slot'}`. 기존 `swapAbility` 는 없앤다(호출하는 곳은 편성소뿐).

### 3-2. 정렬
- `sortMembers(party, key) => Member[]` (새 배열). key: `'joined'`(파티 배열 순서 = 들어온 순), `'level'`(높은 순, 같으면 들어온 순), `'dex'`(도감 번호 `SPECIES[k].dex` 오름차순, 같으면 들어온 순). 메타몽도 목록에 포함(정렬 그대로).

### 3-3. 저장 v6
- v5 → v6: 각 멤버에 `abilityUnlocked: false`. **지금 쓰는 특성은 그대로, 쓰지 않는 특성은 잠김** (사용자 결정 — 뽑기에서 두 번째 특성이 걸렸으면 첫 번째 특성이 잠김). 해금은 "지금 안 쓰는 다른 특성"을 여는 것이라 슬롯 번호와 무관.
- `cleanMember`: `abilityUnlocked` 가 boolean 아니면 false. 특성이 하나인 종은 false. 슬롯 0/1 어느 쪽이든 잠김과 함께 유효.

## 5. 테스트
- 규칙: 해금 결정 3 소비·두 번 해금 거절(already)·부족 거절·특성 하나 거절, 해금 후 setAbilitySlot 공짜, 잠긴 상태 setAbilitySlot 거절, 진화 후 유지. 정렬 3종 + 같은 값 들어온 순. 박스 나누기(31마리 → 2박스).
- 저장: v5 저장(슬롯 1 멤버·슬롯 0 멤버) → v6 에서 해금 true/false; 잘못된 값 → false.
- 화면: 박스 커서 이동·박스 넘기기(31마리), 출전 넣기/빼기 거절 대사, 자세히 보기 페이지 넘기기·다른 동료, 특성 페이지 해금 → 바꾸기 → 저장 호출, 진화의돌 메뉴 활성 조건, 마을 표지판으로 박스가 열림(기존 town 테스트 갱신).

## 6. 빌더 체크 뒤 정리 (내 결정, 바꿔도 됨)
- **해금은 멤버마다**, 결정은 계열 뿌리 공용(지금과 같음). 뽑기는 이미 있는 계열을 결정으로 주므로 한 계열 멤버는 보통 하나.
- **해금하면 바로 그 특성으로 바뀐다** (한 번에). 그 뒤 "이 특성으로 바꾸기" 로 공짜 왕복.
- 특성 페이지의 결정 수는 계열 뿌리 결정(`game.shards[lineRoot]`).
- 정렬 단축 키: 새 키 `S` → 이벤트 `{type:'sort'}` (input.js 추가) + 머리줄 클릭. 정렬·박스 번호·커서는 **이번 실행 동안 기억**(모듈 변수) — 진화 뒤 다시 열어도 그대로, 커서는 진화한 멤버에. 저장 데이터엔 안 넣음.
- 화면 크기: 왼쪽 패널 폭 104, 격자 6×24=144 (x 108~252), 머리줄 14, 격자 5×24=120 (y 16~136), 출전 줄 y 140~188. 한 박스 30칸 고정.
- 메타몽도 격자에 포함(칸 수·박스 수에 포함). 메타몽 메뉴의 출전 줄은 비활성 + 기존 거절 대사.
- 커서: 빈 칸에는 못 감(마지막 동료 칸에서 멈춤). 격자 맨 아래 줄에서 아래 → 출전 줄 가장 가까운 자리, 출전 줄에서 위 → 격자 맨 아래 줄. 격자 왼끝/오른끝에서 좌우 → 이전/다음 박스(같은 줄, 동료 있는 칸으로 당김).
- 능력치: `statsAt(SPECIES[k].base, level)` (특성·랭크 없음). 기술: `MOVES[id]` 의 name/type/category/power/accuracy/range + `ui.shapeLabel(move)`.
- 저장 호출: 출전 넣기/빼기, 해금, 특성 바꾸기 때마다 `onSave()`.
- API 이름은 새로: `createBox({ game, onBack, onEvolve, onSave })` (src/game/box.js), `createSummary` 는 box 안 하위 화면. `party.js` 삭제, town 테스트 두 개 새 API 로 다시 씀. `evolutionHint`·`fitLines` 는 `src/game/memberText.js` 로.

## 7. 빌더 재량
아이콘 크기·배치 세부, 깃발 모양, 능력치 막대 색·최대값, 정렬 상태 저장 여부, 페이지 탭 모양, 파일을 progress.js 에 둘지 새 파일로 나눌지.
