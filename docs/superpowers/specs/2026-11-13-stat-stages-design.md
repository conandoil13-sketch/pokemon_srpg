# 능력치 랭크 + 변화기 — 설계 스펙

- 작성일: 2026-11-13
- 상태: 사용자 리뷰 대기
- 선행: HP 배율 ×(1.6 + Lv/100) (미커밋, 이 작업 브랜치에 함께 들어감), 뽑기·출전 편성(main `14b1ba8`)

## 1. 목표

능력치를 올리고 내리는 **변화기**(칼춤, 울음소리, 고속이동 …)와 공격기의 **능력치 부가효과**(깨물어부수기 방어↓ 20%, 인파이트 자신 방어·특방↓)를 넣는다. 랭크는 **일정 턴 뒤 풀린다**.

### 성공 기준
1. 습득표의 능력치 변화기를 배우고, 전투에서 자신·아군·적에게 쓸 수 있다.
2. 랭크는 −6~+6, 본가 배율로 공격·방어·특공·특방·스피드에 적용, 명중·회피는 랭크당 ±8%p.
3. 랭크 변화는 **3턴** 뒤 풀린다 (같은 능력치를 다시 바꾸면 단계는 누적, 남은 턴은 3으로 갱신).
4. 공격기의 능력치 부가효과가 확률대로 발동한다.
5. 적 AI 도 변화기를 합리적으로 쓴다.
6. 화면: 유닛 정보창에 랭크 표시, 랭크가 바뀔 때 대사·화살표 연출.
7. `npm test` 통과, 브라우저에서 버프·디버프·부가효과·만료가 보인다.

### 범위 밖
상태이상(마비·화상·독·잠듦·혼란 — 다음 단계), 급소 랭크, 랭크 초기화·복사·교환 기술(검은안개·자기암시 등), 날씨·필드, 회복기, 고정 데미지기.

## 2. 데이터 (PokeAPI)

`tools/fetch-pokeapi.js` 가 기술마다 추가로 저장:
- `target`: PokeAPI target 이름
- `statChanges`: `[{ stat, change }]` (stat: attack/defense/special-attack/special-defense/speed/accuracy/evasion)
- `statChance`: `meta.stat_chance` (0 이면 100%)
- `effectKind`: `meta.category.name` (`net-good-stats`, `damage+raise`, `damage+lower`, …)

**배울 수 있는 기술(`learnable`)** = 공격기(위력 있음) **또는** 변화기 중 `statChanges` 가 있고 대상이 §3 표에 있는 것. 그 외 변화기(상태이상·회복 등)는 계속 건너뛴다.

## 3. 대상 · 범위 (SRPG 규칙)

| PokeAPI target | 게임에서 | 범위 |
|---|---|---|
| `user` | 자신 | 사용자 칸 |
| `selected-pokemon`, `selected-pokemon-me-first`, `random-opponent` | 적 1 | 사거리 `[1,2]` (예외 표로 조정) |
| `all-opponents`, `opponents-field` | 범위 안 모든 적 | 자신 기준 맨해튼 거리 ≤ 2 |
| `ally` | 아군 1 | 사거리 1 (인접) |
| `user-and-allies`, `users-field` | 자신 + 범위 안 아군 | 자신 기준 거리 ≤ 2 |
| 그 외 (`entire-field`, `all-pokemon` 등) | 지원 안 함 → 배우지 않음 | — |

- 범위형(전체)은 대상이 0이어도 사용 가능하지만 메뉴에서는 대상이 없으면 회색.
- 변화기는 **명중률 판정**을 받는다 (적 대상만, 회피 랭크 적용). 자신·아군 대상은 항상 성공.
- 데미지는 없으므로 상성·면역은 보지 않는다 (예외 없음).

## 4. 랭크 규칙

- 유닛 상태: `stages = { atk, def, spa, spd, spe, acc, eva }` (−6~+6), `stageTurns = { … }` 남은 턴.
- 배율 (공·방·특공·특방·스피드): `n ≥ 0 → (2 + n) / 2`, `n < 0 → 2 / (2 − n)`.
- 명중·회피: 명중률 += `8 × (명중 랭크 − 대상 회피 랭크)` %p, 최종 0~100.
- 적용 위치: `damage.js` 의 A/D 계산, `hitChance` 의 스피드 비교(유효 스피드)와 명중 보정, AI 의 순서(유효 스피드).
- 변화가 생길 때: 단계 누적·클램프. 이미 ±6 이면 "더 이상 오르지 않는다/떨어지지 않는다" 메시지, 남은 턴은 갱신하지 않는다.
- **지속**: 변화가 생긴 능력치의 남은 턴 = 3. **그 유닛 편의 페이즈가 끝날 때** 1씩 줄고, 0 이 되면 그 능력치 단계 0 으로 복귀 + "○○의 공격이 원래대로 돌아왔다" 표시.
- 층이 끝나면 전부 초기화 (유닛은 층마다 새로 생성되므로 자동).
- 기절하면 사라짐.

## 5. 공격기 부가효과

- `effectKind` 가 `damage+raise` → **사용자**에게, `damage+lower` → **맞은 대상**에게 `statChanges` 적용.
- 확률 `statChance` (0 = 100%). 공격이 빗나가거나 면역이면 발동 안 함. 대상이 기절하면 대상 쪽 효과는 생략.
- 예: 인파이트(자신 방어·특방 −1, 100%), 깨물어부수기(대상 방어 −1, 20%), 바위깨기(대상 방어 −1, 50%).

## 6. 전투 흐름 · 화면

- 행동 메뉴에 변화기도 나온다 (기술 이름 옆 작은 "변화" 표시). 정보창: 분류 "변화", 대상("자신"/"적 전체"/…), 효과 요약("공격 +2").
- 대상 선택: 적 1·아군 1 은 기존처럼 대상 고르기, 자신·범위형은 범위를 보여 주고 확인.
- 연출: 맵 위 공격 연출과 같은 흐름에서 데미지 대신 대상 위에 화살표(▲ 빨강 / ▼ 파랑)와 "공격 +2" 팝업, 대사 "○○의 공격이 크게 올라갔다!" (±1 "올라갔다", ±2 "크게", ±3 이상 "매우 크게").
- 유닛 정보창: 랭크가 있으면 아래에 "공+2 방−1 …" 한 줄과 남은 턴.
- 예상 데미지 창은 랭크를 반영한다.

## 7. 적 AI

`planEnemyAction` 이 변화기 후보도 점수로 비교:
- 자신 버프: 이 턴에 공격 가능한 적이 없거나, 버프 후 다음 턴 기대 데미지 증가량 × 1.5 가 이번 턴 최선 공격 점수보다 크면. 이미 +2 이상이면 제외.
- 적 디버프: 대상 수 × (그 능력치 랭크로 줄어드는 아군 기대 데미지 추정) 로 점수. 대상 0 이면 제외.
- 같은 버프를 연속으로 남발하지 않도록, 남은 턴이 2 이상인 능력치는 다시 올리지 않는다.

## 9. 테스트

- `stages.test.js`: 배율 표(−6~+6), 클램프와 "더 이상" 판정, 누적 + 남은 턴 갱신, 페이즈 종료 감소·만료, 명중 ±8%p 와 0~100 클램프.
- `damage.test.js`: 공격 +2 → 기대 데미지 2배, 방어 −1 → 1.5배, 스피드 랭크가 회피 계산에 반영.
- `battle.test.js`: 칼춤(자신 +2), 울음소리(거리 2 안 적 전체 −1, 밖은 영향 없음), 아군 대상(1~4세대엔 해당 기술이 거의 없으므로 테스트용 가짜 기술 데이터로), 부가효과 100%/확률(rng 고정), 빗나감·면역 시 부가효과 없음, 대상 기절 시 생략, 3턴 후 만료.
- `data.test.js`: 칼춤·울음소리·고속이동 learnable, 대상 매핑, 상태이상 전용 기술(전기자석파)은 여전히 learnable 아님.
- `ai.test.js`: 공격 대상이 없으면 버프, +2 이상이면 버프 안 함, 범위 안 적이 없으면 범위 디버프 안 함.
- 브라우저: 칼춤 → 정보창 표시 → 3턴 뒤 원래대로, 적이 울음소리 사용, 인파이트 후 자신 방어 하락.
