# 던전 추가 가이드 (난이도 곡선 규칙)

새 던전(스테이지)을 만들 때 이 규칙을 따른다. 숫자는 `src/data/dungeons.js` 한곳에, 검증은 `tools/difficulty-report.js` 와 데이터 테스트가 한다. 설계 근거: `docs/superpowers/specs/2026-11-15-difficulty-curve-design.md`, 밸런스 리뷰: `codex-reviews/`.

## 1. 던전 하나에 꼭 있어야 하는 것
| 필드 | 뜻 | 규칙 |
|---|---|---|
| `unlock` | 이 던전을 여는 앞 던전 id (분기면 id 배열 — 그중 하나 돌파) | `stageSlots` 가 자동으로 채움. 첫 던전만 `null` |
| `floors` | 층 수 | 마지막 층이 보스 층 |
| `baseLevel` | 층별 기준 레벨 배열 (길이 = floors) | 층마다 같거나 올라감. 첫 층은 **앞 던전 레벨 상한 − 2 안팎** (앞에서 상한까지 키운 아군이 살짝 유리하게 시작) |
| `budget` | 층별 위협도 예산 배열 | 던전 안에서 **엄격히 증가**. 위협도 = 레벨 × 종족값 합 / 100 |
| `types` | 테마 타입 | 적 후보는 이 타입 중 하나 이상 |
| `early` | 1~2층 전용 초반 종 목록 | 모두 `types` 를 만족하는 1단계 종, 그 던전의 "동네 첫 풀숲" 느낌 |
| `stageCap(f)` | 층별 진화 단계 상한 | 지금 규칙 그대로 |
| `bstCap` | 일반 적 종족값 합 상한 | 보스는 +80 |
| `boss.levelBonus` | 보스 = 마지막 층 기준 + 이 값 | 지금 3 |
| `levelCap` | 이 던전을 돌파하기 전까지의 레벨 상한 | **= 이 던전 보스 레벨** (마지막 층 기준 + levelBonus) |

## 2. 레벨 상한 (배지처럼)
- 상한 = 아직 돌파하지 않은 던전 중 해금 사슬에서 가장 앞 던전의 `levelCap`.
- 모든 던전을 돌파했으면 마지막 던전의 `levelCap` 그대로. **새 던전을 사슬 끝에 붙이면 자동으로 그 던전 상한이 다음 단계가 된다.**
- 상한을 넘은 경험치(전투·사탕)는 버린다. 뽑기 합류 레벨도 상한까지.

## 3. 층 구성
- 유형: 무리형 30 · 보통형 50 · 준보스형 20 (1~2층은 무리 40 · 보통 60, 최대 4마리).
- 깊을수록 예산이 무작위로 더 커질 수 있다: 1~2층 0, 그 뒤 층마다 +5%p, 해금 사슬 뒤쪽 던전일수록 +5%p, 최대 +25% (`budgetBonusMax`). 새 던전은 자동으로 더 큰 변동 폭을 갖는다.
- 굴린 예산을 넘지 않게 한 마리씩, 최소 2마리.
- 같은 시드의 지형·상자·날씨는 바뀌면 안 된다(적은 별도 난수).

## 4. 새 던전을 넣을 때 확인 순서
1. `dungeons.js` 에 위 필드를 채운다(`levelCap` = 보스 레벨).
2. `npm test` — 데이터 테스트가 필드 누락·`early` 타입·예산 증가·사슬 연결을 검사한다.
3. `node tools/difficulty-report.js` — 층별 위협도 중앙값이 오르는지, 첫 층이 앞 던전 마지막 일반 층보다 지나치게 높지 않은지 본다.
4. 결과를 `codex-reviews/` 에 짧게 기록하고, 실제로 한 판 해 본다.


## 임시 스테이지와 대체 (2026-11-17)
- 신오 2개 뒤의 8자리는 `src/data/fillerStages.js` 의 `fillerStage(n)` 곡선으로 만든 임시 단계(시련의 들판·동굴)다. 숫자는 그 파일 위쪽 상수(`START`·`SPAN`·`FLOORS`·`BUDGET_PER_LEVEL`·`BUDGET_STEP`)로 조정한다.
- 진짜 새 맵을 만들면 위 필드를 다 채운 던전 객체를 `REPLACED[n]` 에 넣는다. `unlock` 은 비워 둬도 자리 순서대로 다시 이어지고, 레벨 상한 규칙도 그대로 따라온다.
- 예전 저장은 불러올 때 깬 던전의 다음 단계를 자동으로 연다(`unlockFromCleared`).

## 낙엽더미 (`piles`, 2026-11-17)
던전에 `piles: [최소, 최대]` 가 있으면 층마다 그만큼 낙엽더미를 놓는다 (`floorgen.placePiles`, 별도 난수라 다른 던전 결과는 그대로). 열리지 않은 더미는 지형 문자 `*` — `canEnter` 가 막으므로 이동·밀어내기·순간이동·AI 가 저절로 피한다. 아군이 이동을 마친 칸 상하좌우 옆 더미는 `arrive` 가 연다 (포켓몬 60%: 그 칸에 적 + 레벨만큼 기습, HP 1 남김 / 상자 40%: 바로 전리품). 그림은 `theme: 'autumn'` 일 때 `render/autumnTiles.js`.

## 맵 크기 (`size`, 2026-11-18)
던전에 `size: [W, H]` 가 있으면 그 크기로 층을 만든다 (없으면 16×12). 시련 단계는 `mapSizeFor(시작 레벨)` — 40 미만 16×12 · 40~59 18×13 · 60 이상 20×14 (`src/data/mapSize.js`). 넓은 맵은 지형 덩어리 수를 면적비로 늘리고, 적·예산·상자는 그대로.

## 해변 (`sea`, 2026-11-22)
- `sea: true` → `floorgen.seaBand`: 위/아래 가장자리 바다 띠(깊이 H/4 또는 +1, 출발 3열 제외), 물때 등급 a(해안 첫 줄 `,`)·b(둘째 줄 `~`)·c(늘 `~`). 띠와 그 옆 한 줄엔 지형 덩어리 없음. 결과에 `tide: { a, b }`. 섬: 60%, 4×3(모래 2 + 둘레 깊은 물), 섬 상자 `island: true` 1개 확정. 별도 난수(4000·4050·4100·4150·4200).
- 물때: `core/tide.js` — 라운드 1~3 = 0, 4~6 = +1, 7~9 = 0, 10~12 = −1 반복. `endPhase` 가 적용, 한 라운드 전 `tidePreview`.
- `pileSpecies`: 더미에서 나오는 종 고정 · `minorTypes`: 그 타입만 가진 종은 뽑히면 70% 한 번 다시 · `bossTypes`: 보스 후보 타입 제한. 그림은 `theme: 'beach'` 일 때 `render/beachTiles.js`.

## 맵 그림 품질 기준 (2026-11-22, 사용자 결정)
???시티(`src/render/cityTiles.js`)를 **최소 기준**으로 삼는다. 새 맵 그림은 이보다 대충이면 안 된다.
- **외곽선**: 건물·나무·소품은 어두운 1px 외곽선. 위로 솟는 것은 땅 그림자(반투명)까지.
- **빛 방향**: 왼쪽 위에서 빛 — 위·왼쪽 가장자리 밝게, 아래·오른쪽 어둡게. 큰 물체는 오른쪽·아래로 그림자.
- **바닥 무늬**: 단색 칸 금지. 타일 무늬(보도블록 줄눈·음영, 잔디 결, 아스팔트 자갈)를 월드 좌표로 이어 칸 경계가 티 나지 않게. 다른 바닥이 만나는 곳엔 경계(연석·돌 테두리·물가).
- **디테일 밀도**: 건물이면 지붕 장식·창문(유리 반사)·문·차양 같은 2~3단계 묘사, 변형 여러 개(색·모양)를 해시로 섞음.
- **기믹 오브젝트**(워프 판·더미 등)는 바닥과 확실히 구분되는 형태 + 작은 애니메이션.
- **배치가 그림을 돕게**: 나무는 아스팔트 위가 아니라 공원 안, 건물은 거리처럼 줄지어 — 생성 규칙도 그림에 맞춘다.
- **확인**: 브라우저에서 실제 층을 띄워 스크린샷으로 보고 최소 두세 번 다듬는다 (테스트 통과만으로 끝내지 않음).

## 분기 단계 (2026-11-22)
- `REPLACED[n]` 에 맵 **배열**을 넣으면 그 자리가 분기 단계: 같은 곡선, `stage`·`branch` 가 붙고 목록에 `6-1 이름` 으로 나옴. 임시 스테이지는 빠짐.
- 해금(`branchUnlocks`): 1→여럿 다 열림 · 같은 수는 짝끼리 · 2→3 은 첫 맵 공통 + 나머지 짝 · 여럿→1 하나라도. 레벨 상한은 단계 중 하나만 깨도 다음 단계로. 설계: `docs/superpowers/specs/2026-11-22-branch-stages-design.md`.
